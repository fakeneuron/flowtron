# FE-002 | cross-project viz

[← PLAN.md](../PLAN.md) · 🌱 Starter (filed 2026-05-08)

## 🌱 Starter context

_Captured 2026-05-08 during a design discussion immediately after the v1.2.0 release ([[CORE-048]]). Promote to full tasknote at `/task` checkout — Phase 1 Discovery should drift-check the file paths and confirm the architecture choices below still hold._

### Why this exists

User runs viz across multiple projects (flowtron, fintown, InvisiPaw, photard, natabula). Current model is per-project: each adopter runs `cd _project/flowtron/viz && npm run dev` from their own checkout, reading their own `_project/PLAN.md` via relative path. Two friction points:

1. **Port collisions.** Multiple Vite instances on the strictPort 5173 (set by `e7e786b`) — second instance refuses to start. User has to stop one before opening another.
2. **No cross-project view.** When working in any project, the user wants to see the viz for *that* project (and ideally swap to others) without juggling terminals/ports.

The fix is to promote `~/code/flowtron/viz/` from "flowtron's own viz" to "the global viz for everything under `~/code/`": one instance ever, fixed port, project selector in the UI swaps which project is rendered.

### Solution shape

- **One global Vite dev server**, lives in `~/code/flowtron/viz/`. Single instance ever. `strictPort: 5173` stays — second instance erroring out is the collision-detection mechanism.
- **Workspace scan at boot + on file change.** Glob `${FLOWTRON_VIZ_WORKSPACE:-~/code}/*/_project/PLAN.md` to discover projects. For each match, the project's directory name (e.g., `fintown`, `InvisiPaw`) becomes the project label; project root is the parent of `_project/`. Skip dirs without an `_project/PLAN.md`.
- **Per-project loader.** For each discovered project, load `_project/PLAN.md` AND the full `_project/tasknote/*.md` directory (active tasknotes — for frontmatter, status, subtask progress, drill-down). Tasknote-path resolver moves from cwd-relative to absolute project paths.
- **Project selector in header rail.** Single-select (dropdown or chip group). Picking a project swaps the **active project** — the existing single-project view (FE-001 vertical list / FE-004 frontmatter cards / FE-006 starter chip / FE-010 keyboard nav / FE-012 inbound back-refs / FE-008 row density / FE-009 dark mode) re-renders against that project's data unchanged. **Not** a combined Kanban — user explicitly chose per-project view, swappable via selector.
- **File-watcher widening.** FE-011's chokidar watcher watches every discovered project's `_project/PLAN.md` + `_project/tasknote/` (recursive). Auto-refresh on any change, scoped to whichever project is active (or refresh all and let React reconcile).
- **Adopter-docs update.** `claude/CLAUDE-snippet.md` ("Bumping the pinned flowtron version" section), `README.md` (`## Visualizer` section), and `docs/MIGRATION.md` updated to recommend running flowtron's global viz from `~/code/flowtron/viz/` instead of from each adopter's `_project/flowtron/viz/`. Adopter-side `_project/flowtron/viz/` continues to *work* (read-only submodule, unchanged) but is no longer the recommended path.

### Files to touch (preliminary survey — drift-check at promotion)

- `viz/src/workspace.ts` — **new**. Workspace scanner: env-var-driven glob, returns `Array<{name: string, root: string, planPath: string, tasknoteDir: string}>`.
- `viz/src/parser.ts` — accepts a project descriptor (or PLAN content + tasknote dir), returns project-tagged tasks. Keep core parsing the same; widen the loader.
- `viz/src/tasknote.ts` — tasknote-path resolver moves to absolute paths from the project descriptor.
- `viz/src/ui/App.tsx` — adds `activeProject` state + project-selector component in the header rail; passes the active project's data into the existing list.
- `viz/src/ui/<new>/ProjectSelector.tsx` — **new** UI component (follow chip / select pattern from existing header rail).
- `viz/src/main.ts` (or wherever the dev-server file watcher lives) — widen chokidar to watch every discovered project.
- `viz/vite.config.ts` — likely no change (port already pinned in `e7e786b`); verify env var is plumbed if needed.
- `viz/tests/*` — workspace-scanner tests, project-selector tests, parser project-tagging tests.
- `claude/CLAUDE-snippet.md` — "Visualizer / global viz" addition.
- `README.md` `## Visualizer` section — global-viz invocation pattern.
- `docs/MIGRATION.md` — note that adopters should run flowtron's global viz instead of per-project.

### Explicitly out of scope

- **Removing adopter-side `_project/flowtron/viz/` invocation.** It still works (the submodule is unchanged); we're just no longer recommending it. Hard-deprecation can be a follow-up if the global viz proves stable.
- **Combined Kanban view** (all projects' tasks in one list). User explicitly chose project selector instead — single project visible at a time.
- **Cross-project task linking.** `[[TASK-ID]]` wikilinks remain project-scoped; cross-project resolution would be a separate feature if ever needed.

### Decisions locked in this conversation

| Decision | Choice | Rationale |
|---|---|---|
| Workspace root config | env var `FLOWTRON_VIZ_WORKSPACE`, default `~/code/` | Cheap, future-proof; lets users with non-`~/code/` layouts opt in |
| Project naming | Directory name (e.g., `fintown`) | Zero config; matches user's mental model |
| Cross-project layout | Per-project view with selector (not combined Kanban) | User wants the same single-project view they have today, swappable |
| Tasknote scope | Read each project's full `_project/tasknote/*.md`, not just PLAN.md | Required for frontmatter cards, status, subtask progress, drill-down |
| Server location | `~/code/flowtron/viz/` (no relocation) | Already there; flowtron is the source of truth |
| Port | Keep `strictPort: 5173` from `e7e786b` | Single-instance enforcement is the collision-detection mechanism |
| Task shape | Single full task (not epic) | Self-contained feature in one `viz/` codebase; clean Discovery phase suffices |
| Filing shape | Starter (rich design captured now; promote to full at `/task`) | Preserves this conversation's design context across the chat boundary |

### Open at promotion (Phase 1 should resolve)

- **Selector UI: dropdown or chip group?** Lean: chip group if ≤ ~6 projects (matches FE-006 / FE-015 chip pattern); dropdown if user's `~/code/` has more. Decide at Phase 1 by counting actual projects.
- **Project-selector state persistence?** Lean: `localStorage` so refresh doesn't kick the user back to project[0]. Decide at Phase 1.
- **Scoped state on project switch.** Filters / keyboard-nav focus / scroll position — reset on project switch, or preserve per-project? Lean: reset (simpler; mirrors fresh-load semantics). Decide at Phase 1.
- **Chokidar watch scope.** Watch `_project/tasknote/` recursively per project, or only flat `*.md` at top level? Lean: flat — archive subdirs don't need watching. Decide at Phase 1.
- **Skip rules for non-flowtron-adopting dirs under workspace root.** Anything in `~/code/*` without `_project/PLAN.md` is silently skipped. Edge case: project with PLAN.md but no `_project/tasknote/` — render PLAN tasks without tasknote enrichment (don't crash).
- **Adopter-side viz directory deprecation timing.** This task: update docs to recommend global viz; keep `_project/flowtron/viz/` working. Hard-removal: deferred to a follow-up if/when global viz proves stable.
