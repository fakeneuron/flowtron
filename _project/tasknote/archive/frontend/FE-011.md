**Implementation Notes:**

- **Pattern:** the existing `flowtronApi` plugin already follows the Vite middleware idiom. Added a third `server.middlewares.use('/api/events', ...)` alongside the existing two — same shape.
- **Server (`viz/vite.config.ts`):**
  - Set up a `chokidar.watch([PLAN_PATH, join(TASKNOTE_DIR, '*.md')], { ignoreInitial: true, depth: 0 })` watcher in `configureServer`.
  - 200ms debounce coalesces editor save bursts into a single broadcast.
  - 30s heartbeat (`: ping\n\n`) keeps the SSE socket warm.
  - Cleanup on `server.httpServer.close` (clears timers, closes watcher, ends client streams).
  - Guarded the entire SSE setup behind `if (server.httpServer)` — vitest spins up Vite in middleware mode (no `httpServer`), so the watcher + heartbeat would otherwise hang the test runner. (Caught during Phase 3.)
- **Client (`viz/src/ui/App.tsx`):** new `useEffect` opens an `EventSource('/api/events')` and calls `void load()` on each `change` event. Browser-default reconnect handles transient drops.
- **Dependency:** `chokidar@^3.6.0` added as direct devDependency (was already present transitively via vite/vitest).
- **No tests added:** the dev plugin is not unit-tested today (consistent with existing convention); end-to-end SSE testing requires a real dev server, which is out of scope. Verified manually via curl + content edits — confirmed 3 separate edits produce 3 separate `change` events through the SSE stream.
- **Bug found in Phase 3 — chokidar + atomic-save edits:** initial implementation worked for content-append edits but missed `sed -i ''`-style atomic replacements (sed renames a temp file over the original, breaking chokidar's file-level fs.watch on the now-stale inode). UI auto-refresh wasn't firing when PLAN.md was edited via sed. Fix: added `usePolling: true, interval: 200` to the chokidar options. Polling-based stat is reliable across all editor save strategies (atomic rename, in-place write, etc.) and the cost is trivial (~31 stat calls per 200ms for our file set).

**Final Summary:**

Replaced the manual Refresh button with chokidar-watched SSE auto-refresh. Three small, surgical changes:

- `viz/package.json` — `chokidar: ^3.6.0` added as direct devDependency (was already transitively present via vite/vitest).
- `viz/vite.config.ts` — `flowtronApi` plugin gains a third middleware `/api/events` that streams `event: change` SSE messages on file edits to `_project/PLAN.md` + top-level `_project/tasknote/*.md`. 200ms debounce coalesces editor save bursts; 30s heartbeat keeps the socket warm; cleanup ties to `server.httpServer.close`. SSE setup is gated behind `if (server.httpServer)` so vitest's middleware-mode Vite instance doesn't hang.
- `viz/src/ui/App.tsx` — single `useEffect` opens `EventSource('/api/events')` and calls the existing `load()` on each `change` event. Refresh button untouched.

Two course-corrections during the task:
1. **vitest hang** (caught at first `npm test`) — the chokidar watcher + setInterval kept the test runner alive after tests finished. Fixed by gating the watcher setup on `server.httpServer` (vitest spins up Vite without one).
2. **Atomic-save invisibility** (caught during Playwright verification) — chokidar's file-level `fs.watch` on macOS doesn't survive `sed -i ''`-style atomic replacement (sed renames a temp file over the original; the watcher's fd points to the now-orphan inode). Real-world editors (VS Code, vim with `set backupcopy=no`) use the same pattern. Fixed with `usePolling: true, interval: 200`. Negligible CPU for ~30 watched files; reliable across all editor save strategies.

End-to-end verified live in Playwright: PLAN.md edit → row text updates without page reload, expanded detail panel survives the refresh, 0 console errors. 53/53 vitest tests pass; `tsc --noEmit` clean.
