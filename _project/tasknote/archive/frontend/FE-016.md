# FE-016 | viz consume archive

[← PLAN.md](../PLAN.md) · ✅ Completed · 🔗 [[CORE-036]] [[FE-007]]

## 🎯 Goal

Extend the viz to read `_project/tasknote/archive/<area>/*.md` so completed rows render their archived Goal/Acceptance/Subtasks instead of empty click-expand stubs, while still distinguishing "never had a tasknote" from "archived".

## ✅ Acceptance

- [x] `GET /api/archive` returns a JSON array of `Tasknote` objects parsed from every `_project/tasknote/archive/<area>/*.md` file (recursive across area subdirs).
- [x] App.tsx `load()` fetches `/api/archive` in parallel with `/api/plan` and `/api/active`, and merges archive tasknotes into the same `tasknotesById` map (active wins on ID collision — should never happen, but defensive).
- [x] Click-expanding a completed PLAN.md row whose ID has an archive file renders the archived `🎯 Goal` / `✅ Acceptance` / `🧩 Subtasks` (via existing `TaskDetail` flow), not the PLAN.md stub.
- [x] Completed rows with no archive file (e.g., the 10 bootstrap CORE rows) still fall back to `task.description` and still show the `no tasknote` pill in `TaskRowInner`.
- [x] Completed rows that DO have an archive file no longer show the misleading `no tasknote` pill.
- [x] SSE watcher in `vite.config.ts` `flowtronApi` also watches `_project/tasknote/archive/**/*.md`, so closure-archive transitions and manual archive edits trigger a refresh.
- [x] No regression on active-row rendering, starter detail, or epic subtask rendering; existing parser/tasknote tests still pass.
- [x] `tsc --noEmit` clean; `npm run test` green; visual confirmation via Playwright on at least one completed-with-archive row + one completed-no-archive row.

**Implementation Notes:**

- **`viz/vite.config.ts`:**
  - Added `ARCHIVE_DIR = join(TASKNOTE_DIR, 'archive')` constant.
  - Watcher now passes three globs: `PLAN_PATH`, `join(TASKNOTE_DIR, '*.md')`, `join(ARCHIVE_DIR, '*', '*.md')`. Bumped `depth: 0 → depth: 2` (archive root → area dir → file). Active-tasknote depth is unaffected because the glob already locks the path level.
  - New `/api/archive` middleware: `readdir(ARCHIVE_DIR, { withFileTypes: true })` to enumerate area subdirs, then per-area parallel `readdir + parseTasknote`, then `Promise.all().flat()`. Wraps the area-readdir in a try/catch returning `[]` so fresh projects without an archive dir still 200.
- **`viz/src/ui/App.tsx`:** `load()` now fetches three endpoints in parallel; archive seeds the merged map, active overwrites on collision (defensive — collision should never happen because the closure motion moves the file). Net diff: ~6 lines.
- **No changes** to `tasknote.ts`, `parser.ts`. The existing `tasknotesById.get(task.id)` lookup and `showNoTasknote = !tn && ...` derivation in `TaskRowInner.tsx:42-46` automatically resolve once archived tasknotes land in the same map.

- **Mid-execution course-correction — PLAN-wins-on-status patch.** Visual confirmation surfaced that ~5 archive files have stale `status:` frontmatter that was never flipped at closure (`CORE-024`, `CORE-036`, `CORE-042.6`, `CORE-042.7` still say `in-progress`; `CORE-021` says `de-scoped`). Faithful render meant CORE-036 displayed an `IN PROGRESS` chip in the Completed section. User chose option (a) "PLAN wins on status" — small viz patch, leave the partial subtask bars untouched as a "closed with loose ends" signal. Implementation:
  - Added `effectiveStatus(task, tn)` helper in `viz/src/ui/utils.ts`. Returns `'completed'` when `task.completed === true`; otherwise `tn?.frontmatter?.status ?? null`.
  - Wired through `TaskRowInner.tsx` (status chip + PhaseDots starter-suppression), `TaskDetail.tsx` (status chip + starter detection), and `App.tsx` (`matchesFilter`, `presentStatuses`, `inProgress` count).
  - Side effect: bootstrap rows under `## Completed` (the 10 no-tasknote rows) now also get a "Completed" status chip alongside their existing `no tasknote` pill. Mildly redundant with the section header but consistent.
