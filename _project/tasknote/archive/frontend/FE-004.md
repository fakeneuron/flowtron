## 🛠️ Phase 2: Execution

- [x] **Pattern survey** — `parser.ts` is single-purpose (PLAN.md only); added sibling `src/tasknote.ts` rather than overloading. `App.tsx` uses inline Tailwind utility classes (no UI lib / no component classes); matched that. Vite plugin uses simple async middleware with try/catch; extended in same shape. **Architecture choice:** parse frontmatter server-side in the Vite plugin (gray-matter runs in Node where it's bulletproof; smaller client bundle; future FE-002 will want server-side filesystem scans anyway).
- [x] Implemented the minimal solution
- [x] Updated/added tests for non-trivial behavior
- [x] Ran targeted tests on changed files

**Implementation Notes:**

- **New deps:** `gray-matter` (server-side, used by Vite plugin), `react-markdown`, `remark-gfm` (client-side, GFM checkbox + table rendering).
- **New file `src/tasknote.ts`** — exports `Tasknote`, `TasknoteFrontmatter`, `TasknoteStatus` types + `parseFrontmatter()`, `extractSection()`, `parseTasknote()`. Coerces YAML date values (gray-matter parses `created: 2026-05-01` as a JS `Date`) → ISO date strings; rejects unknown status/model values; returns `frontmatter: null` for archived tasknotes with no YAML block (backwards-compat).
- **`vite.config.ts`** — `/api/active` now returns `Tasknote[]` (was `string[]`): reads each `.md` file in `_project/tasknote/`, parses frontmatter + extracts Goal/Acceptance/Subtasks sections in one pass.
- **`src/ui/App.tsx`** — replaced `activeIds: Set<string>` state with `tasknotesById: Map<string, Tasknote>`. Cards merge PLAN.md task data with frontmatter when present. Frontmatter-derived UI (priority badge, status chip, tag chips, due-date pill, "Open in VS Code" link, click-to-expand markdown) only lights up for active tasks with parsed frontmatter — completed/archived cards keep FE-001's minimal rendering. Added tag + status multi-select filter chip rows; both compose with the existing search predicate. Search predicate extended to also match `tags.join(' ')`, `status`, and `frontmatter.title`.
- **Section extractor (`extractSection`)** — finds an H2 heading by substring match (e.g. "Goal" matches `## 🎯 Goal`), captures lines until the next H2 or `---` divider. Lets the inline-expanded card show only the spec layer (Goal/Acceptance/Subtasks), not Phase 1-4 logs.
- **"Open in VS Code" mechanism** — pure-frontend `<a href="vscode://file{absolutePath}">`; no backend `/api/open`. `e.stopPropagation()` on the link to prevent triggering the card's expand toggle.
- **Backwards-compat verified:** in dev, FE-004 (active, with frontmatter) renders rich card; CORE-016, FE-003, all Low/Future/Completed cards render with original minimal layout. Zero regression on FE-001 behavior.
