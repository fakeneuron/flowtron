**Discovery Notes:**

**Salvage assessment from `legacy/`:**
- **Reusable as-is:** `vite.config.ts` (trivial), `tsconfig.json`, `tailwind.config.ts`, `postcss.config.cjs`, `eslint.config.mjs`, `src/main.tsx`, `src/styles.css`, `src/ui/utils.ts` (`groupBy`), `index.html`, dependency list in `package.json` (drop `pg`/`dotenv` — Postgres-mode artifact).
- **Reusable shape, full rewrite:** `src/ui/App.tsx` — Kanban shell, Tailwind classes, search input, counter row are reusable patterns; `Plan`/`TaskNote` types and JSON-fetch logic must be replaced by a markdown parser + the new column axis (priority, not status).
- **Not reusable:** `legacy/_project/plan.json`, `legacy/_project/tasknote/*.json`, `legacy/scripts/flowtron-cli.mjs`, `legacy/.flowtron/` (db-mode), `legacy/dist/samples/` (old format).

**Drift finding:** PLAN.md's FE-001 line implied `legacy/` was the visualizer to revive, but post-CORE-001 reset, the data model under it changed entirely (JSON → markdown). User absorbed this above; PLAN.md re-scoped accordingly.

**Decisions captured (via AskUserQuestion):**
1. **V1 scope:** Minimal single-project read-only Kanban MVP. Cross-project deferred to FE-002.
2. **Hosting:** New `viz/` directory in flowtron repo. Standalone npm package — `cd viz && npm install && npm run dev`. (No root `package.json` exists today and we shouldn't add one for a sub-tool.)
3. **Model:** opus (multi-file frontend with parsing + design decisions).
4. **Column axis:** By priority — Critical / High / Medium / Low / Future / Completed (six columns). "In Progress" shown as a badge/glow on cards that have an active tasknote file in `_project/tasknote/`.

**Defaults committed (no separate question — sensible MVP shape):**
- PLAN.md is read by a Vite dev-server middleware plugin that serves `/api/plan` (raw filesystem read of `../_project/PLAN.md` on each request — simple, supports cross-project later).
- Active task detection = directory listing of `../_project/tasknote/*.md` (filename → task ID). No parsing of tasknote contents in MVP.
- UI controls: priority-section columns + per-card priority is redundant when grouped by priority, so cards show `ID — description` + (optional) `In Progress` badge + (for Completed) date.
- Search box (substring match across ID/description). No filter chips in MVP.
- Manual refresh button. No file watcher / HMR for PLAN.md (Vite HMR doesn't watch files outside the workspace by default; the middleware re-reads on every request, so refresh is enough).
- Drop `legacy/` postgres deps (`pg`, `dotenv`); drop `zustand` (single-component state, `useState` suffices for MVP); drop `eslint-plugin-security` (no security-sensitive paths).
- Stack: Vite 5 + React 18 + TypeScript 5 + Tailwind 3 (same major versions as legacy/; modest bumps OK).

**Out of scope for MVP (deferred to FE-002 or later):**
- Cross-project scanning across `~/code/*/_project/PLAN.md`.
- Tasknote drill-in / phase visualization.
- Edit / drag-to-move / write-back to PLAN.md.
- File watcher / live updates.
- Subtask hierarchy beyond flat rendering of `CORE-EPIC-009.x` IDs (epic + subtasks shown as siblings for V1; nesting is FE-002 polish).

**Execution Steps:**

1. **Scaffold `viz/` directory** with `package.json` (Vite + React 18 + TS + Tailwind), `tsconfig.json`, `vite.config.ts`, `tailwind.config.ts`, `postcss.config.cjs`, `index.html`, `.gitignore`, and `src/{main.tsx, styles.css, ui/App.tsx, ui/utils.ts}` skeleton.
2. **Write `src/parser.ts`** — pure function `parsePlan(markdown: string): Task[]` that walks `_project/PLAN.md`, tracks current `## <Section>` heading, and extracts task lines matching `- [ ] **<ID>** — <description>` or `- [x] **<ID>** — <description>. Completed YYYY-MM-DD.`. Returns `{ id, description, priority, completed, completedDate? }`. Handles nested subtask lines (indented `  - [ ]`) by treating them as siblings tagged with parent epic ID.
3. **Write `viz/vite.config.ts` plugin** that adds two dev-server endpoints: `GET /api/plan` (fs-reads `../_project/PLAN.md` and returns raw text) and `GET /api/active` (returns `readdirSync('../_project/tasknote/')` filtered to `*.md` and stripped to task IDs). Path-resolved relative to repo root, hardcoded for V1.
4. **Write `src/ui/App.tsx`** — fetches `/api/plan` + `/api/active` on mount, parses, renders six priority columns side-by-side (horizontal scroll on narrow viewport), each column lists tasks. Cards show ID + description + (if active) `In Progress` badge + (if completed) date. Search input filters across ID/description. Refresh button re-fetches.
5. **Polish styles** — Tailwind classes, sensible spacing, color-code priority columns subtly, ensure scrollable when long.
6. **Manual smoke test** — `cd viz && npm install && npm run dev`, open browser, verify against current flowtron PLAN.md (3 open in Future + 1 in Medium + 1 in Low + ~13 completed). Confirm CORE-EPIC-009 + its 5 subtasks render visibly.
7. **Lint + typecheck** — `npm run lint`, `npm run build` clean.
8. **Update root `README.md`** — add a brief "Visualizer" section pointing at `viz/` with the run command. Update `.gitignore` if needed (already covers `node_modules/`/`dist/`).
9. **Visual confirmation from user** before declaring Phase 3 done.

**Implementation Notes:**

**Pattern survey:** The Vite + React 18 + TS + Tailwind shell mirrors `legacy/` directly (same major versions, same file shape). The new shape is the markdown parser (`src/parser.ts`) and the Vite dev-server middleware (`vite.config.ts` `flowtronApi` plugin) — neither exists anywhere else in flowtron. Justified as new because (a) the data model is markdown not JSON, so legacy's `JSON.parse` path doesn't apply, and (b) cross-project FE-002 will extend the same middleware shape, making it the right abstraction to introduce.

**Files created:**
- `viz/package.json` — flowtron-viz@0.1.0; deps trimmed from legacy (dropped `pg`, `dotenv`, `zustand`, `eslint-plugin-security`, `prettier`, `tests/`).
- `viz/tsconfig.json` — same compiler options as legacy plus `@types/node` + `vitest/globals` for the middleware + tests.
- `viz/vite.config.ts` — React plugin + `flowtronApi()` plugin: `/api/plan` (fs-read of `../_project/PLAN.md`) + `/api/active` (readdir of `../_project/tasknote/`).
- `viz/tailwind.config.ts`, `viz/postcss.config.cjs`, `viz/index.html`, `viz/src/main.tsx`, `viz/src/styles.css` — straight ports from legacy with title bumped to "Flowtron — PLAN.md".
- `viz/src/parser.ts` — `parsePlan(markdown): Task[]`. Tracks current `##` heading, matches task lines via regex (handles `- [x]`/`- [ ]`, IDs like `CORE-001`/`CORE-EPIC-009`/`CORE-009.1`, optional "Completed YYYY-MM-DD" extraction, strips `**` bold from descriptions).
- `viz/src/parser.test.ts` — 6 tests covering open / completed / subtasks / non-section / bold-strip / empty-section. All pass.
- `viz/src/ui/utils.ts` — `groupBy` ported verbatim from legacy.
- `viz/src/ui/App.tsx` — six priority columns (color-tinted), search box (substring across id+description), refresh button, "In progress" badge sourced from `/api/active` ∩ unchecked tasks. ~140 lines.
