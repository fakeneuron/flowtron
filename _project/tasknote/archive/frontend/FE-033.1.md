### Clarifying-question outcomes (resolved 2026-05-16)

1. **Palette × theme** — *Two axes (Recommended).* Palette and theme are independent: user picks palette (default / linear / github) and toggles theme (light / dark) separately. Each palette ships matching light + dark variants. Default palette + light theme = today's appearance unchanged. Matches Linear / GitHub / Notion mental model (their themes are paired light/dark).
2. **Token strategy** — *Runtime token swap via React hook (Recommended).* `PALETTES = Record<PaletteName, Palette>` lives in `constants.ts`; `usePalette()` hook reads `visibilityPrefs.palette` + the active light/dark theme and returns the active palette's tokens. ~12 use sites switch from `STATUS_BADGE['in-progress']` to `palette.STATUS_BADGE['in-progress']`. No Tailwind config changes; type-safe; trivial palette add (new key in the record).
3. **Picker placement** — *SettingsModal fieldset (Recommended).* New "Palette" radio fieldset between Density and Detail panel, parallels Density's pattern. Reuses CORE-098.3 modal infrastructure; zero new header surface.
4. **MVP palette count** — *3 palettes: Default + Linear + GitHub (Recommended).* Notion deferred (low differentiation vs Default's neutrality per the survey below). Filed slate = `.2` architecture + `.3` Linear + `.4` GitHub + `.5` picker UI + `.6` audit.

### Reference-system survey

**Linear** — distinctive indigo / purple / teal accent family with restrained warm secondaries (amber for warning, emerald for success). Default-dark posture with a clean light pairing. Sectioning is monochrome (no priority tint stripes); status carries the color. **Translation to viz's 12 tokens:** STATUS_BADGE picks Linear's purple/indigo/amber/rose/emerald set; SECTION_TINT picks a muted complement per priority (cool gradient: Low=sky → Medium=teal → High=indigo → Critical=rose → Future=violet); ROW_HIGHLIGHT stays indigo (Linear's brand color anchors this naturally). Strong character; differentiates clearly from Default.

**GitHub** — purple / blue / green accent family, more saturated than Linear, with a warmer light mode. Distinct dark-mode signature: charcoal grays + saturated accent pops. Status colors map cleanly (GitHub uses green/red/yellow/blue/purple semantically). **Translation to viz's 12 tokens:** STATUS_BADGE picks GitHub's green/gray/blue/red/purple semantic set; SECTION_TINT uses purple-violet-magenta gradient for higher priorities + cool blue for lower; ROW_HIGHLIGHT swaps to yellow/amber to match GitHub's "modified" highlight convention (justifies a per-palette highlight hue divergence — viable because the amber-collision was resolved by *separating roles*, not by reserving amber globally; under the GitHub palette, amber stays bound to the highlight role and a different hue takes "active phase"). Higher visual character vs Linear's restraint.

**Notion (deferred per Q4)** — warm-gray neutrals + restrained accent set (red/yellow/green/blue/purple at low saturation). Closer to Default's neutrality than to Linear/GitHub's character. Deferred from MVP because it adds less differentiation per LOC of curation work. Re-evaluate post-MVP if user wants a fourth.

### Storage scope (assumption recorded, not user-confirmed)

Palette joins `visibilityPrefs.palette: 'default' | 'linear' | 'github'` (per-project, alongside `density`). **Rationale:** density is the closest analog — both are aesthetic prefs that benefit from per-project variation (different projects might warrant different palettes when dogfooding the viz across repos). Reuses the existing `flowtron-viz-prefs:<project>` storage key; bumps schema to `version: 2` (with `version: 1` reads back-filling `palette: 'default'` so old prefs upgrade silently). Alternative considered + rejected: global key (`flowtron-viz-palette`) — simpler but loses per-project flexibility and creates two parallel pref systems (visibilityPrefs + standalone). Flagging this as an explicit assumption rather than a Q5 because the density precedent is clear; user can flip in `.2` if the per-project framing turns out wrong.
