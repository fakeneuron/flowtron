**Discovery Notes:**

- `matchesFilter` (App.tsx:83–110) derives `fm = tn?.frontmatter ?? null`. At line 93-95, if `statusFilter.size > 0` and `fm` is null, it immediately returns false — the bug.
- Fix: derive `effectiveStatus: TasknoteStatus = fm?.status ?? (task.completed ? 'completed' : 'not-started')`, then compare against `statusFilter`. One-liner change; frontmatter continues to win when present.
- `task.completed` is a `boolean` set by the parser from the `- [x]` mark (parser.ts:146).
- No clarifications needed. Explicit assumptions: (1) "Starter" / "In progress" / "Blocked" statuses can only apply when frontmatter is present — tasks without a tasknote will only ever get `completed` or `not-started` as their effective status; (2) tag filter behavior (lines 88–91) is correct and unchanged.

**Implementation Notes:**

Replaced `App.tsx:93-95`:
```ts
// before
if (statusFilter.size > 0) {
  if (!fm) return false;
  if (!statusFilter.has(fm.status)) return false;
}

// after
if (statusFilter.size > 0) {
  const effectiveStatus: TasknoteStatus = fm?.status ?? (task.completed ? 'completed' : 'not-started');
  if (!statusFilter.has(effectiveStatus)) return false;
}
```
Frontmatter wins when present; without frontmatter, `task.completed` (boolean from parser) drives the effective status.
