### Resolution of the audit's literal-flip ambiguity

The audit's one-liner ("flip `EpicRow`'s `selectedId: string | null` prop to `isSelected: boolean`") doesn't address EpicRow's children loop, which depends on `selectedId` to compute per-child selection (`selectedId === c.id` for each SubtaskRow child). User-resolved 2026-05-10 via AskUserQuestion: **add `isSelected` (own row, mirrors TaskRow), keep `selectedId` (children-only purpose, becomes clearer once divorced from own-row check)**. Two-prop interface, distinct purposes per prop. Minimal change, no architectural disruption.

### Helper home

`viz/src/ui/utils.ts` — fits the existing mold (`groupBy`, `effectiveStatus`, `buildInboundRefs`: pure viz-specific helpers). New file would be premature for one function.

### Helper signature

```ts
export function rowOutlineClass(isHighlighted: boolean, isSelected: boolean): string {
  if (isHighlighted)
    return 'border-amber-400 ring-2 ring-amber-300 dark:border-amber-500 dark:ring-amber-600';
  if (isSelected)
    return 'border-slate-200 ring-2 ring-sky-400 dark:border-slate-800 dark:ring-sky-600';
  return 'border-slate-200 dark:border-slate-800';
}
```

Two-boolean signature (rather than `highlightId: string | null, taskId: string, isSelected: boolean`) keeps the helper agnostic of the data model — it just says "here are two visual states; give me the right class." Callers do `highlightId === task.id` at the callsite, where the comparison is already cheap and readable.
