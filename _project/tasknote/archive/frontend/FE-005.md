**Implementation Notes:**

- **Pattern survey:** existing `viz/` codebase puts inline sub-components at the bottom of `App.tsx` (cf. the existing `Section` component). Followed that pattern for the new components (`PrioritySection`, `EpicRow`, `TaskRow`, `TaskRowInner`, `SubtaskRow`, `TaskDetail`, `DetailSection`, `Chevron`, `PhaseDots`, `SubtaskProgress`, `ModelChip`, `RelatedChip`). Pure helpers (`activePhaseIndex`, `countChecklist`, `groupTasks`) went into the appropriate domain modules (`tasknote.ts`, `parser.ts`) so they're testable without importing TSX.
- **`tasknote.ts` additions:** `ChecklistCounts` interface; `countChecklist(markdown)` (regex `/^\s*-\s+\[([ xX])\]/`); `activePhaseIndex(phases)` (earliest-incomplete logic, treats zero-total as active); `phases: ChecklistCounts[]` and `subtasksProgress: ChecklistCounts` added to `Tasknote`. `parseTasknote` extracts each `Phase N` section using existing `extractSection` and counts via `countChecklist`.
- **`parser.ts` additions:** `TaskNode { task, children }` interface; `groupTasks(tasks)` reconstructs epic-parent ↔ child relationships from ID convention (`<AREA>-EPIC-<N>` ↔ `<AREA>-<N>.<SUB>`). Single forward pass; orphan subtasks fall through as standalone top-level nodes for safety.
- **`App.tsx` rewrite:** old 6-column Kanban (`COLUMNS` constant, horizontal-scroll flexbox of `<section>`s) entirely removed. New vertical layout uses `SECTIONS` priority list + `PrioritySection` collapsible blocks; `Completed` section starts collapsed via `useState(new Set(['Completed']))`. Epic detection in the section render: `node.children.length > 0 || /-EPIC-/.test(node.task.id)` (the regex covers the empty-children case).
- **Filtering:** `matchesFilter(task)` runs once per top-level node — epic parents match independently and their children always ride along (visible inside the collapsible block when expanded).
- **Related-tasks chip click → `navigateToTask(id)`:** finds the task via `tasks.find`, removes its priority from `collapsedSections` (no-op if already expanded), expands the parent epic if `id` matches the subtask pattern, then on next `requestAnimationFrame` calls `scrollIntoView({ behavior: 'smooth', block: 'center' })` + `setHighlightId(id)`. Highlight class (`border-amber-400 ring-2 ring-amber-300`) auto-clears after `HIGHLIGHT_MS = 1500`.
- **DOM-nesting fix:** initial render had a `<button>` chip inside a `<button>` row (React DOM-nesting warning). Resolved by scoping the row's expand-toggle `<button>` to just the ID + title cluster; the right-side signal cluster (with its own `<button>` chips and `<a>` link) is a sibling `<div>` inside the row, not nested inside the toggle button.
