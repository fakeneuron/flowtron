### Assumptions (no clarifications needed)

1. **`WIKILINK_PATTERN` via rename, not alias.** Rename the internal `WIKILINK` const to `WIKILINK_PATTERN` and export it (single source). Two internal call sites in `parser.ts` (L72, L81) get updated in the same pass. An alias would leave the original name as a parallel surface that can drift — the whole point of this task is to collapse parallel surfaces.
2. **`isEpic(node: TaskNode): boolean`, not `isEpic(id: string)`.** Both call sites already have a `TaskNode` in scope, and the `node.children.length > 0` check is inherently node-shaped. An id-only signature would force callers to also OR the `children.length` check, defeating the helper.
3. **`isEpic` uses anchored `EPIC_ID` regex internally**, not the relaxed `/-EPIC-/.test(...)`. The anchored form is canonical and matches the parser's own grouping logic; the relaxed form is identical in behavior for valid flowtron IDs but admits hypothetical malformed inputs. Tightening is a free correctness win.
4. **`getSubtaskParentEpicId` returns the full epic ID (`CORE-EPIC-057`), not the bare key (`CORE-057`).** Matches the App.tsx:298 use case exactly (the call site reconstructs the epic ID by hand today). The existing private `subtaskParentKey` helper returns the bare key for `epicByKey` map lookup — different concern, kept as-is.
5. **No new exported regex helpers beyond the three named.** `EPIC_ID` and `SUBTASK_ID` regexes stay private — callers don't need raw regex, they need predicate/derivation helpers.

**Implementation Notes:**

### `parser.ts` changes

- **L59** — `const WIKILINK = ...` → `export const WIKILINK_PATTERN = ...` (renamed + exported)
- **L72, L81** — internal callers updated to `matchAll(WIKILINK_PATTERN)`
- **L105-107** — added `export function isEpic(node: TaskNode): boolean { return node.children.length > 0 || EPIC_ID.test(node.task.id); }` (anchored regex; tighter than the relaxed `/-EPIC-/` substring test that was at the call sites)
- **L109-111** — added `export function getSubtaskParentEpicId(id: string): string | null { const m = SUBTASK_ID.exec(id); return m ? `${m[1]}-EPIC-${m[2]}` : null; }`

### Consumer changes

- **`App.tsx`** — imports broaden to include `getSubtaskParentEpicId` + `isEpic`; the `epicIds` derivation collapses to `if (isEpic(node)) set.add(node.task.id)`; the `navigateToTask` subtask handler simplifies from regex-parse-then-rebuild to a single `getSubtaskParentEpicId(id)` call.
- **`PrioritySection.tsx`** — imports `isEpic`; the local `const isEpic = ...` shadow is removed; map body becomes `if (isEpic(node)) { ... }`.
- **`WikilinkMarkdown.tsx`** — local `WIKILINK_TEXT` const removed; imports `WIKILINK_PATTERN` from parser; `seg.replace(WIKILINK_PATTERN, ...)` substituted.

### LOC delta

- `parser.ts`: +9 LOC (WIKILINK rename = 0, two new exports = 9)
- `App.tsx`: −5 LOC (regex-parse-then-rebuild → single helper call)
- `PrioritySection.tsx`: −1 LOC
- `WikilinkMarkdown.tsx`: −1 LOC
- **Net: ~+2 LOC**, but with single-source-of-truth correctness gain. Matches FE-018's "~10-15 LOC + correctness" estimate when accounting for the new helpers being declarations vs. inline expressions.

### Shared `/g` regex safety

`WIKILINK_PATTERN` carries the `/g` flag and is now consumed by three callers (parser.ts × 2 via `matchAll`, WikilinkMarkdown.tsx × 1 via `String.replace`). Both `matchAll` and `replace` handle `lastIndex` correctly with `/g` — no contamination risk. Verified by passing test suite.
