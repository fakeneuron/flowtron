FE-007 (predecessor, 2026-05-04) extracted all 14 components from App.tsx, shrinking it from 902 → 319 lines and explicitly leaves `## 🧩 Subtasks` referencing FE-014. Existing tests (`parser.test.ts`, `tasknote.test.ts`) are pure-logic Vitest with no DOM — this task introduces the RTL pattern.

**Decisions (from clarifying questions):**
- Test location: colocated, `viz/src/ui/App.test.tsx` (mirrors `parser.test.ts` next to `parser.ts`).
- Stack: Vitest + `@testing-library/react` + `@testing-library/user-event` + `@testing-library/jest-dom` + `jsdom`.
- Scope: only the four PLAN-cited behaviors. `useKeyboardNav` is FE-010 territory; pure leaf-component renders are out.

**Implementation hazards:**
- jsdom does not implement `Element.prototype.scrollIntoView` — must stub in setup file or each test will throw inside `navigateToTask`.
- jsdom does not ship `EventSource` — App's `useEffect` opens `/api/events` on mount; needs a global stub before render.
- `requestAnimationFrame` is provided by jsdom but fires asynchronously; tests must `await` (or use `waitFor`) to observe the highlight + scroll side effects.
- `HIGHLIGHT_MS = 1500` — tests asserting highlight clear should use `vi.useFakeTimers()` to avoid wallclock waits.
- Triggering `navigateToTask` from the UI requires a wikilink click. The cleanest entry point is to expand a row that contains a `[[<AREA>-<N>.<sub>]]` reference rendered by `WikilinkMarkdown`/`RelatedChip`, then click it.

**Pattern intent:** establish a single-file-per-component-source convention. `App.test.tsx` covers App.tsx logic surfaces; future component tests follow the same naming + setup-file usage. The `renderApp()` fixture seeds fetch + EventSource so individual tests stay focused on behavior, not boilerplate.

**Implementation Notes:**

**Pattern survey:** existing `parser.test.ts` and `tasknote.test.ts` are pure-logic Vitest, colocated next to source (`parser.ts`, `tasknote.ts`). No prior RTL pattern. Adopted the same colocation rule for component tests (`App.test.tsx` next to `App.tsx`); shared infra in `viz/src/test/` since it's cross-component.

**Files added:**
- `viz/src/test/setup.ts` — registers jest-dom matchers, stubs `Element.prototype.scrollIntoView`, `EventSource` (jsdom 25 ships neither for our needs), and `window.matchMedia` (ThemeToggle's `theme.ts` calls it on mount).
- `viz/src/test/fixtures.ts` — exports `makeTasknote(partial)` (fills sensible defaults for the `Tasknote` shape) and `renderApp({ plan, active?, archive? })` which seeds `globalThis.fetch` for `/api/plan`, `/api/active`, `/api/archive` and renders `<App />`.
- `viz/src/ui/App.test.tsx` — four describe blocks, one per cited behavior.

**Files changed:**
- `viz/vite.config.ts` — `defineConfig` switched to `vitest/config` so the `test` block is type-checked; `Plugin` type still imported from `vite`. Added `test: { environment: 'jsdom', setupFiles: ['./src/test/setup.ts'], globals: false }`.
- `viz/package.json` — added devDeps `@testing-library/react`, `@testing-library/user-event`, `@testing-library/jest-dom`, `jsdom@^25` (pinned to 25 because jsdom 27 requires Node ≥20.19 and the dev machine runs 20.18).

**Test design notes:**
- `matchesFilter` test seeds three tasks with two tags × two statuses to demonstrate AND-intersection between dimensions (alpha + in-progress + query="200" cascades down to one row).
- `navigateToTask` test uses fake timers (`vi.useFakeTimers({ shouldAdvanceTime: true })`) so the 1500ms `HIGHLIGHT_MS` timer can be advanced explicitly. Spies on `Element.prototype.scrollIntoView` per test (the setup file only stubs it; the spy proves it was called with `{ behavior: 'smooth', block: 'center' }`). Triggers via the `RelatedChip` button rendered on a Low-priority task whose tasknote `relatedTasks` references the subtask.
- Expand-on-click test queries by `getByRole('button', { expanded: false, name: /CORE-100/ })` so it targets the `aria-expanded` row toggle specifically (TaskRowInner's button), not any nested control.
- Status badge test scopes queries via `within(statusGroup)` so it doesn't collide with the in-row status badges (which render the same label text with a different role).
