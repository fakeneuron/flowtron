**Implementation Notes:**

- **Pattern survey.** No existing two-cluster grid pattern in `viz/src/ui/`. Existing siblings (`SubtaskRow`, `EpicRow`, header filter rail) all use single flex rows. Chose CSS grid for the chip strip because the user picked the grid approach in Discovery and the two-cluster split benefits from explicit alignment between rows (signal columns line up, metadata columns line up). A grouped flex would visually achieve the same look but lose cross-row alignment.
- **`TaskRowInner.tsx` diff.** `flex shrink-0 items-center justify-end gap-1.5 min-w-[30rem]` → `grid shrink-0 grid-cols-[auto_auto] items-center gap-x-4`, with two inner `flex items-center justify-end gap-1.5` clusters. Signal cluster: PhaseDots / SubtaskProgress / BlockerChip. Metadata cluster: no-tasknote placeholder / ModelChip / tags / RelatedChip / due / status badge / extraRightSlot. The `min-w-[30rem]` reservation removed; title now claims all unused width. `PRIORITY_BADGE` constant removed (moved to `TaskDetail`); priority span, completed-date span, and VS Code link `<a>` removed from row.
- **`TaskDetail.tsx` diff.** Imported `Priority` from `../parser`; defined `PRIORITY_BADGE` (the same record `TaskRowInner` previously owned). New thin metadata header strip rendered above the existing Goal/Acceptance/Subtasks (or starter context, or no-tasknote description fallback): priority badge + "Completed YYYY-MM-DD" text + VS Code link (right-aligned via `ml-auto`). Each conditional: priority shown when frontmatter has it; completed-date shown when `task.completed && task.completedDate`; VS Code link shown when tasknote exists. Header strip itself hidden when none of the three apply.
- **Tier 1 sizing bumps.** `PhaseDots.tsx`: dot size `h-1.5 w-1.5` → `h-2 w-2`. `SubtaskProgress.tsx`: bar `h-1.5 w-12` → `h-2 w-16`, label `text-[10px] text-slate-500` → `text-[10px] font-medium text-slate-600`. `BlockerChip.tsx`: `text-[10px]` → `text-[11px] font-medium`.
- **No new tests.** No UI component tests exist yet (FE-014 will scaffold that). Behavior of parser/tasknote modules unaffected — visual-only refactor.
