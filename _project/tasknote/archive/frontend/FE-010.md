# FE-010 | viz keyboard nav

[← PLAN.md](../PLAN.md) · ✅ Completed · 🔗 [[FE-007]]

## 🎯 Goal

Add keyboard shortcuts to the viz so the dashboard can be operated without a mouse: `/` focuses search, `j/k` arrow-nav rows, `Enter` expands, `r` refreshes, `Esc` collapses detail / clears filters.

## ✅ Acceptance

- [ ] `/` focuses the search input from any non-typing context; pressing `/` while typing in search does not intercept (literal slash allowed).
- [ ] `j` / `k` move a single-row "selection cursor" through the flat visible list (top-level rows + epic subtask rows when their epic is expanded); selected row is visibly marked with a distinct (non-amber) ring.
- [ ] j/k auto-scroll the selected row into view; selection clamps at list bounds (no wrap).
- [ ] `Enter` on a non-epic row toggles its detail panel. On an epic row: expands the children list if collapsed, else toggles the detail panel.
- [ ] `r` reloads PLAN/active/archive (same path as the Refresh button).
- [ ] `Esc` cascades one-step-per-press: close open detail → clear all filters (query + tag + status) → blur search input.
- [ ] Shortcuts do not fire while typing in the search input (except `/` is a literal slash there and `Esc` still runs the cascade).
- [ ] Modifier-key combinations (Cmd/Ctrl/Alt/Meta + key) are not intercepted.
- [ ] No regression in existing mouse-driven behavior (click-to-expand, Refresh button, filter chips, wikilink chip nav).
- [ ] Lint + typecheck clean on changed files.
- [ ] Visual confirmation from the user.

## 🧩 Subtasks

- [ ] Add `selectedId: string | null` state and a `searchInputRef` to `App.tsx`; wire the ref to the existing search `<input>`.
- [ ] Compute a memoized flat `visibleIds: string[]` from `bySection` + `collapsedSections` + `expandedEpicIds` (top-level row IDs in section/order, with epic children inserted when their epic is expanded).
- [ ] Implement the global keydown handler (likely a `viz/src/ui/useKeyboardNav.ts` hook to keep App.tsx tidy; inline if it stays small) covering `/`, `j`, `k`, `Enter`, `r`, `Esc` with the typing/modifier guards.
- [ ] `/` handler: focus the search input, preventDefault. No-op when search is already focused.
- [ ] `j`/`k` handler: move `selectedId` along `visibleIds` (first/last when nothing selected; clamp at bounds); call `scrollIntoView({ block: 'nearest' })` on the row element.
- [ ] `Enter` handler: if selected ID is an epic — toggle children if collapsed, else toggle `expandedId`. Else (non-epic) toggle `expandedId`.
- [ ] `r` handler: call `load()`.
- [ ] `Esc` handler: cascade — if `expandedId !== null`, clear it; else if `query || tagFilter.size || statusFilter.size`, clear all three; else if active element is the search input, blur it.
- [ ] Add `isSelected` prop to `TaskRow`, `EpicRow`, `SubtaskRow`; apply a distinct sky ring (e.g., `ring-2 ring-sky-400 dark:ring-sky-600`). Amber highlight takes precedence on visual overlap.
- [ ] Plumb `selectedId` from `App.tsx` through `PrioritySection` to row components.
- [ ] Manual smoke test in the dev server: each shortcut, the cascade, the typing/modifier guards, no-mouse-needed flow end-to-end.
- [ ] Lint + typecheck on changed files.
- [ ] Request visual confirmation from the user.

**Design decisions (confirmed by clarifying questions):**
1. **j/k scope:** flat across all visible rows, including epic subtask rows when their epic is expanded.
2. **Enter on epic:** smart — expand children if collapsed, toggle detail panel if children already open.
3. **Cursor visual:** distinct (sky-coloured) ring, separate from the existing amber highlight (which stays reserved for the wikilink-click "where I just navigated from" signal).
4. **Esc:** one-step cascade per press — detail → filters → blur.

**Assumptions (logged for the record):**
- Shortcuts are disabled while typing in the search input (so `j`, `k`, `r`, `Enter` don't intercept), with two exceptions: `/` is a literal slash inside the input, and `Esc` always runs the cascade.
- Modifier-key combos (Cmd/Ctrl/Alt/Meta + key) are never intercepted — leaves browser/OS shortcuts untouched.
- j/k clamps at list bounds (no wrap-around). First `j` when nothing selected → first row; first `k` when nothing selected → last row.
- Subtask rows are j/k-navigable but `Enter` is a no-op on them (no detail panel and no children to expand).
- `r` and the existing Refresh button share the same `load()` callback.
