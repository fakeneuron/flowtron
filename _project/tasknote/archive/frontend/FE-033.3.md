### Clarifying-question outcomes (resolved 2026-05-17)

User delegated both curation calls to my professional-designer judgement ("use your best judgement thinking like a professional graphic designer" + "same as previous question"). Decisions locked below, with the rationale visible at the Phase 1→2 gate so the user can redirect before code lands.

**Q1 — Section-tint approach.** Chose **C (muted hint — slate background, hue-tinted border)**. Rationale: (a) honors Linear's actual product UI restraint (their app uses near-monochrome sections with accent dots/borders) without losing viz's priority-as-section-color cue entirely; (b) gives the three palettes distinct visual territory — Default = warm-saturated candy, Linear = cool-restrained slate-with-accents, GitHub (`.4`) likely lands at saturated-pop on charcoal; (c) pure-monochrome (B) sacrifices viz's at-a-glance section scanning, while pure-recolor (A) feels like a hue rotation rather than a re-design. C threads the needle.

**Q2 — Anchor hue.** Chose **indigo**. Rationale: (a) Linear's actual brand IS indigo (`#5e6ad2`-adjacent) — a "Linear palette" without indigo as the brand voice is inauthentic; (b) the objection to indigo (matches Default's ROW_HIGHLIGHT) only mattered under Q1=A where section tints already overlapped Default; under Q1=C the slate-leaning section approach differentiates strongly from Default regardless, so indigo's repeated use across STATUS_BADGE.in-progress + ROW_HIGHLIGHT + PRIORITY_BADGE.Medium becomes Linear's intentional brand voice, not a collision; (c) the amber-collision lesson from CORE-098.2 was about overlapping *roles*, not overlapping *hues* — here indigo serves four distinct roles (highlight border, status badge, priority badge, section accent) which is the intended pattern.

**Q3 (implied, locked silently) — Section-tint gradient hue per priority.** Mapping:
- Critical → **rose** (Linear's destructive accent — softer than Default's red)
- High → **amber** (Linear retains amber for warnings, even with brand indigo elsewhere)
- Medium → **indigo** (the most-common priority section carries the brand)
- Low → **sky** (preserved from Default; works in the cool family)
- Future Opportunities → **violet** (preserved — aspirational/experimental cue)
- Completed → **emerald** (preserved — universal "done")

### Design rationale (locked palette, surfaces at Phase 1→2 gate)

**Three accent slots, slate everywhere else.** Linear's discipline is "neutral surfaces, accent dots". Translating to viz's 12 tokens:
- **Brand slot = indigo** — STATUS_BADGE.in-progress, ROW_HIGHLIGHT, ROW_HIGHLIGHT_SUBTASK, PRIORITY_BADGE.Medium, SECTION_TINT.Medium border
- **Selection slot = teal** — ROW_SELECTION, ROW_SELECTION_SUBTASK. Shifted off Default's sky to avoid visual clash with Low priority's sky section-border (selection ring on a Low-priority row would be sky-on-sky in Default; teal disambiguates and adds a Linear-restrained cool second accent)
- **Warmth slot = amber** — PHASE_DOT.active retained (single warm note inside the cool palette; phase dot is small/contained; strict monochrome reads as boring per designer instinct), PRIORITY_BADGE.High, SECTION_TINT.High border (Linear retains amber for warnings universally)
- **Universal semantic preserves** — emerald for "done" (STATUS_BADGE.completed, PRIORITY_BADGE.Completed, SECTION_TINT.Completed border, PHASE_DOT.filled); rose for "destructive/blocked" (STATUS_BADGE.blocked, PRIORITY_BADGE.Critical, SECTION_TINT.Critical border); lime for "starter/new growth" (STATUS_BADGE.starter); slate for "not-started/neutral" (STATUS_BADGE.not-started, ROW_NEUTRAL, EPIC_ROW_NEUTRAL); violet for "future/aspirational" (PRIORITY_BADGE.Future Opportunities, SECTION_TINT.Future Opportunities border); sky for Low (PRIORITY_BADGE.Low, SECTION_TINT.Low border)

**Section tint string form (all 6 priorities):** `bg-slate-50 border-{hue}-300 dark:bg-slate-900/50 dark:border-{hue}-800`. The slate bg is uniform across the 6 sections; the hue-tinted border carries the priority cue. Restrained, Linear-true, still functionally readable for triage.

**Value-pair preservation for badges** — STATUS_BADGE and PRIORITY_BADGE keep Default's `bg-{hue}-100 text-{hue}-800 dark:bg-{hue}-950 dark:text-{hue}-200` pairing. Pre-validated for ≥4.5:1 contrast across all Tailwind hues we use; no per-token Lighthouse re-check needed within this task (`.6` audit covers the union of all 3 palettes × 2 themes).

**What stays identical to Default** (universal-semantic-preserve discipline; intentional, not laziness):
- STATUS_BADGE: starter (lime), not-started (slate), blocked (rose), completed (emerald) — universal task-state semantics
- PHASE_DOT: filled (emerald-500), active (amber-400 + ring-amber-200/700), inactive (slate-200/700) — preserves amber as the single warm anchor
- ROW_HIGHLIGHT / ROW_HIGHLIGHT_SUBTASK: indigo (Linear brand intentionally matches Default's post-CORE-098.2 indigo highlight pick)
- ROW_NEUTRAL / EPIC_ROW_NEUTRAL: slate-200/800 + slate-300/700 (universal neutral surface)

**What changes vs Default** (the visible Linear character):
- STATUS_BADGE.in-progress: amber → **indigo** (brand anchors the most-shown status)
- SECTION_TINT (all 6): full-color bg → **slate bg + hue-tinted border**; hue mapping shifts Critical red→rose, High orange→amber, Medium amber→indigo (Critical/High/Medium changes; Low/Future/Completed preserved)
- PRIORITY_BADGE: same 3 hue shifts as SECTION_TINT — Critical red→rose, High orange→amber, Medium amber→indigo (cohesion with section borders)
- ROW_SELECTION / ROW_SELECTION_SUBTASK: sky → **teal** (disambiguates from Low's sky border; introduces second cool accent)

**Net change:** ~17 token strings shift inside `PALETTES.linear`. Diff stays inside `constants.ts`; no consumer-file, hook, or test source changes.
