description: File a mid-flow follow-up task — one PLAN.md line + a short conversational context paragraph (no tasknote artifact). Add --park to park an idea or quick fix instead (tiny stub, no review gate, resume inline), or --unattended to file with no operator present. Lighter than /ft-starter-task.
argument-hint: [TASK-ID] [--park [--low|--med|--fut|--high]] [--unattended]
---

Invoke the `ft-file-followup` skill with `args="$ARGUMENTS"`. The skill validates the task ID against PLAN.md when provided, or suggests the next available task ID for review when omitted. It collects task ID / priority / model / title / long-description via AskUserQuestion, enforces the SPEC/tasknote-selection.md §"PLAN.md filing-discipline thresholds" cap (>70w → suggests `/ft-starter-task` instead), drafts a short conversational context paragraph, surfaces both for review, then appends the PLAN.md entry, auto-commits it (`chore: file <ID> follow-up — <shortname>`, staged path-explicitly; skipped when PLAN.md already carried other edits), and delivers the paragraph in chat. Produces zero artifacts on disk beyond the one new PLAN.md line.

**`--park` (or `-p`)** switches to park mode via the `park-mode.md` lazy fragment: auto-allocates a TASK-ID when omitted, takes priority from `--low` → `## Low`, `--med`/`--medium` → `## Medium`, `--fut`/`--future` → `## Future Opportunities`, `--high` → `## High` (any position in args). **No priority flag → one short question, then wait** before writing. With a flag (or after the user answers), writes `.flowtron/sidequest/<ID>.md` + one PLAN line, auto-commits both (`chore: file <ID> park — <shortname>`), skips the review gate and the reconciliation scan, replies in ≤70 words with priority + resume anchor + SHA, then continues the interrupted work inline.

**`--unattended`** runs the operator-less posture, for a closure with no operator present discharging `SPEC.md` §"Deferred hand-off filing". It auto-allocates the TASK-ID, suppresses the AskUserQuestion collection and the review gate, and drafts all five fields itself; the downstream-impact reconciliation scan still runs but applies nothing (its findings travel in the hand-off report instead), and the filing still commits — authorized by the SPEC-imposed duty rather than by a review approval (`SPEC/tasknote-selection.md` §"Filing commits" → "Unattended filing authority"). The filing-discipline cap, the pre-check/skip-on-dirt guard, explicit-pathspec staging, commit-never-push, and no-🏁 all bind exactly as they do attended; anything it cannot answer — an ambiguous area, an ID collision, a still-over-cap description, or a `--park --unattended` combination — terminates with a one-line `⏸ --unattended stop — <cause>` and writes nothing. Not combinable with `--park`.

For tasks with rich context (file survey / design decisions / open questions) that warrant persisting, use `/ft-starter-task [TASK-ID]`. For starting an existing task (starter, follow-up line, or fresh), use `/ft-task <TASK-ID>`. For small file + execute one-shots, use `/ft-micro-task <TASK-ID>`. For opening a new epic, use `/ft-epic-discovery`. For closing one, use `/ft-close-epic`. For bootstrapping a fresh repo with flowtron, use `/ft-new-project`.
