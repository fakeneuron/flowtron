# FE-94.2 | Pin the App seams the suite misses before any restructuring

[← PLAN.md](../PLAN.md) · 🌱 Starter (filed 2026-08-23)

## 🌱 Starter context

_Captured 2026-08-23 during the `/ft-refactor viz/src/ui/App.tsx` depth survey — promote to full tasknote at `/ft-task` checkout._

### Why this exists

First step in the sequence: every later child moves code that `App.test.tsx`
must already pin, or the "behavior-preserving" claim is unverifiable.

The survey found coverage unusually good — `App.test.tsx` (1236 lines, ~70
tests) drives the real `App` through `renderApp()` against a seeded `fetch`,
already pinning navigation, filtering/pruning + counts, project switching,
prefs, all three diagnostics families, SSE disconnect, and completed-bucket
grouping. So this step is a **gap-fill, not a build-out** — a handful of tests,
not a suite.

The gaps are exactly the surfaces FE-94.4/.5/.6 will move.

### Solution shape

- Pin the **view-mode toggle**: the two `list`/`board` buttons render inside
  `role="group"` / `aria-label="View mode"`, carry correct `aria-pressed`,
  clicking `Board` switches the rendered view, and `writeStoredViewMode`
  persists to `localStorage['flowtron-viz-view']`. Today both board tests
  (`App.test.tsx:903`, `:1186`) seed that key directly and never touch the
  buttons — so `updateViewMode` is entirely unexercised.
- Pin the **`listViewEmptySections` copy**: `No tasks in this project` when
  every section is empty vs `No tasks in: <a · b>` when only some are.
- Pin the **"No matches. Press Esc to clear filters."** empty state (query or
  status filter active, `filteredCount === 0`).
- Pin the **header starter suffix**: `· N starter` / `· N starters` from
  tasknotes with `frontmatter.status === 'starter'`, and absent at zero.
- Pin the **error banner**: `projectsError ?? dataError` renders the red strip.
  `renderApp`'s `perProject.fail` seam already supports forcing this.
- Acceptance seeds for Phase 1 to promote into `## ✅ Acceptance`:
  - new tests written and **green before** any restructuring child starts;
  - no source file under `viz/src/` changes in this child — tests only;
  - `npm --prefix viz test` and `npm --prefix viz run typecheck` green.

### Files to touch (preliminary survey — drift-check at promotion)

- `viz/src/ui/App.test.tsx` — new `describe` blocks for the five gaps above.

### Explicitly out of scope

- Any change to `viz/src/ui/App.tsx` — this child is tests only.
- The extractions themselves — FE-94.3 (selectors), FE-94.4 (diagnostics),
  FE-94.5 (header), FE-94.6 (state hooks).
- Broadening coverage beyond the seams the sequence moves; the existing ~70
  tests already carry the rest.

### Decisions locked in this conversation

| Decision | Choice | Rationale |
|---|---|---|
| Characterization level | App-level via `renderApp()` | Matches the existing suite's seam; survives every later extraction unchanged, which is the point |
| Scope of new tests | Only the five unpinned seams | Coverage is already deep; make-work tests dilute the signal |
| Position in sequence | First, blocking everything | Pin before move — the epic's behavior-preservation contract rests on it |

### Open at promotion (Phase 1 should resolve)

- Does asserting the view-mode toggle need a `localStorage` read-back, or is
  asserting the re-render enough? Lean: assert both — persistence is what
  FE-94.6 moves into `useViewPrefs`.
- Real vs fake timers for the empty-state tests. Lean: real timers, per the
  suite-wide convention documented at `App.test.tsx:23-30` (FE-045/FE-089.2).
