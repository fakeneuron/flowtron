# FE-066 | viz-plan-grammar-glyph-tolerance

[← PLAN.md](../PLAN.md) · 🟢 In progress · 🔗 [[FE-EPIC-063]]

## 🎯 Goal

Make `TASK_LINE` in `viz/src/parser.ts` tolerant of three real PLAN.md conventions it currently rejects — the model-suggestion glyph after `[model]`, stacked `[model]` tokens, and a leading status glyph — so the ~149 glyph-carrying rows on flowtron's own board parse instead of dropping into the FE-063.2 diagnostics banner.

## ✅ Acceptance

- [ ] `TASK_LINE` parses rows with a model-suggestion glyph (`🧠`/`🔧`) after `[model]`, space-optional (`[medium]🧠` and `[medium] 🧠`), capturing `model` and ignoring the glyph.
- [ ] `TASK_LINE` parses rows with stacked `[model]` tokens (`[fable] [light]`), capturing the first token as `model` and tolerating the rest.
- [ ] `TASK_LINE` parses rows with a leading status glyph between the checkbox and the bold ID (`- [ ] ⏸ **ID**`).
- [ ] All three tolerances compose (a single row may carry a leading glyph + stacked models + suggestion glyph) and existing grammar (`[!critical]`, `[model]`, `| shortname`, long desc, wikilinks) still parses.
- [ ] New fixtures cover each case; full `viz` parser test suite passes; malformed-token drop behavior is preserved.
- [ ] Real `.flowtron/PLAN.md` produces zero glyph-related `unparsed` diagnostics after the change.
- [ ] SPEC §"Task-line format" reconciled: documents the three parser tolerances.

## 🧩 Subtasks
