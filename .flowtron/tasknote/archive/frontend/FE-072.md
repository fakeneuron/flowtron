## 🎯 Goal

Close a same-project out-of-order refresh race in `useProjectData` with a monotonic load-sequence guard, and upgrade the test `MockEventSource` to a real listener map so the SSE change-refresh and drop→reconnect branches gain coverage.

## ✅ Acceptance

- [ ] New `useProjectData.test.ts` covers: (a) same-project out-of-order load guard, (b) `change` → `refresh`, (c) drop (`error`) → reconnect (`open`) reconciliation refresh, (d) first `open` with no prior drop → no redundant refresh.

**Discovery Notes:** Race mechanism: two rapid `change` SSE events each call `refresh()` → two `load(sameProject, false)` calls. Both see the same `activeProjectRef.current`, so the FE-046 guard passes for both; if the older response resolves last, it overwrites fresh data. A `++loadSeqRef.current` stamp per load + a `loadSeqRef.current !== seq` bail on commit/error/loading fixes it. Discovery surfaced no significant deviation → skip 🛠️.

**Implementation Notes:**
