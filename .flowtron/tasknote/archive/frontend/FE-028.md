## 🎯 Goal

Add a per-project parsed-archive cache for `/api/archive` (invalidated by chokidar) so project switches don't re-readFiles + parse the entire archive tree on every request.

## ✅ Acceptance

- [ ] `/api/archive?project=<P>` warm response < 50ms for fintown (was 1.26s); subsequent requests served from in-memory cache without re-reading/re-parsing files.
- [ ] Chokidar watcher includes each discovered project's `_project/tasknote/archive/**/*.md` (recursive across area subdirs; survives a new area dir like `database/` without code changes).
- [ ] Add/modify/remove of any archive `.md` file invalidates that project's cache exactly once and triggers the existing SSE broadcast; the next `/api/archive` request reflects the change.
- [ ] Per-project isolation: editing project A's archive does not flush project B's cache.
- [ ] In-flight de-dup: concurrent `/api/archive` requests during cold-populate share a single parse cycle (subsumes FE-027 transient-500 race).

### Clarifying questions

User answered the only genuinely ambiguous question: **FE-027 should be subsumed**. With that locked, the design is settled:

- **Cache key:** `project.name` (matches the existing `projects: Map<string, ProjectDescriptor>` keying).
- **Cache value:** `Promise<Tasknote[]>` — storing the promise (not the resolved value) gives in-flight de-dup for free: two concurrent first-time requests both `await` the same in-flight populate, fixing FE-027's race without a separate mutex.
- **Cache granularity:** per-project (PLAN.md wording locks this in: "per-project parsed-archive cache").
- **Warm-up strategy:** lazy. First request to each project populates the cache; cold-start UX is unchanged from today, warm-request UX drops from 1.26s → in-memory. Eager warm-up at server start adds startup cost and complexity for marginal UX (the user only pays the cold cost once per project per server lifetime today).
- **Invalidation scope:** an archive watch event drops ONLY the affected project's cache; PLAN/active-tasknote events do NOT drop archive caches (cheap, just a path-prefix check).
- **Error path:** if `readArchive` rejects, the rejected promise is removed from the cache so the next request retries (otherwise a transient FS error would poison the cache forever). The current `try/catch → 500` shape is preserved.
- **depth bump:** `depth: 1 → 2`. Safe for the existing globs: `planPath` is a file (depth doesn't apply); `tasknoteDir/*.md` is a single-level glob (depth doesn't apply); only the new archive glob actually uses the extra level.

### Out of scope

- **Per-file cache** (`Map<id, Tasknote>`): premature for a 700-file scale. Archive writes are rare (one per closure motion), so the slow re-read happens at most once per closure event; subsequent requests are O(1) from cache. Per-file optimization would only matter if invalidations were frequent and reads scaled to 10K+ tasknotes.
- **Eager warm-up at server start**: see above; lazy is sufficient.
- **Client-side caching of archive data**: not needed; the perf bottleneck is the server-side parse, not transport (JSON payload is 3MB but gzips well and is one-shot per project-switch).
- **FE-026 (bundle code-split)**: separate concern, separate task.

**Implementation Notes:**

### Pattern survey

The `flowtronApi` plugin already holds module-scope state inside the closure (`sseClients`, `debounceTimer`, `watcher`, `heartbeat`, `projects: Map<name, ProjectDescriptor>`). The cache fits the same shape — `Map<string, Promise<Tasknote[]>>` — but the cache contract (in-flight de-dup, error-no-poison, prefix-based invalidation) is interesting enough to warrant a separate testable module. Existing `viz/src/workspace.test.ts` already establishes the right shape for filesystem unit tests (tmpdir + populate + exercise + rm). Extracted the cache to `viz/src/archiveCache.ts` and modeled tests on `workspace.test.ts`.

### Files changed

- **New:** `viz/src/archiveCache.ts` (~60 LOC) — exports `createArchiveCache()` returning `{ get, invalidate, clear }`. Internal `readArchive(project)` is the original `/api/archive` body verbatim with the `safeReaddir` helper inlined. Cache stores `Promise<Tasknote[]>` (not the resolved value) so concurrent first-time callers share one in-flight populate. The `.catch` on the populate promise removes the rejected entry from the cache before re-throwing — error path doesn't poison.
- **New:** `viz/src/archiveCache.test.ts` (~150 LOC, 9 tests) — covers cold-populate, missing-archive-dir tolerance, warm-cache identity, in-flight de-dup, invalidate-then-re-read, prefix miss, per-project isolation, error-no-poison, and `clear()`.
- **Modified:** `viz/vite.config.ts` (~25 LOC delta).
  - Added `import { createArchiveCache } from './src/archiveCache'`.
  - Instantiated `archiveCache` next to `projects` in the plugin closure.
  - Widened `watchPaths` to include `join(p.archiveDir, '**/*.md')`; bumped chokidar `depth: 1 → 2` (covers `archive/<area>/<file>.md`; safe for the existing one-level globs).
  - Switched `watcher.on('all', scheduleBroadcast)` to a payload-aware `(_event, filepath) => { archiveCache.invalidate(filepath, projects.values()); scheduleBroadcast(); }`. The `typeof filepath === 'string'` guard is defensive against chokidar's `unlink`/`error` payload shapes.
  - Replaced the `/api/archive` handler body (~25 LOC inline read+parse) with a single `await archiveCache.get(project)` call (~3 LOC). The `try/catch → 500` shape preserved.
  - Added `archiveCache.clear()` to the `httpServer.close` cleanup symmetric with `watcher?.close()`.
- **Unchanged:** `safeReaddir` in `vite.config.ts` — still used by `/api/active`. Not extracted to avoid a churny refactor unrelated to FE-028.

### Design decisions

- **Promise-valued cache** (vs resolved-value): in-flight de-dup is free; subsumes FE-027's transient-500 race without a separate mutex.
- **Per-project granularity** (vs per-file): PLAN line locked this in, and the math holds — archive writes are rare (one per closure) so re-populating ~700 files at most once per closure is fine, and warm requests are O(1).
- **Lazy populate** (vs eager): cold-start UX is unchanged; warm-request UX drops 1.26s → in-memory.
- **Prefix-based invalidation lookup**: `filepath.startsWith(p.archiveDir)` walks `discovered` once per chokidar event. With ~10 projects this is microseconds; no need for a path → project Map.
- **Error path**: `readArchive(project).catch(err => { delete the cached promise if still ours; rethrow })`. The `if (cache.get(project.name) === cached)` guard handles the race where a second populate has already started before the catch handler runs.

**Final Summary:**

`/api/archive` no longer re-reads + re-parses every archived tasknote on every request. New `viz/src/archiveCache.ts` exposes a per-project `Map<projectName, Promise<Tasknote[]>>` with three operations: `get(project)` (lazy populate, in-flight de-dup), `invalidate(filepath, projects)` (path-prefix match → drop owning project), and `clear()`. The `flowtronApi` plugin in `viz/vite.config.ts` instantiates one cache per server lifecycle, widens chokidar's watch list to include each discovered project's `archive/**/*.md` (depth 1→2), and switches `watcher.on('all', ...)` to a payload-aware handler that invalidates the affected project's cache before scheduling the SSE broadcast. The handler at `/api/archive` collapses from a 25-LOC inline read+parse to `await archiveCache.get(project)`. FE-027's transient-500 race is subsumed: the cache stores promises (not resolved values), so concurrent first-time callers share one in-flight populate — the race window no longer exists.

Net diff: +60 LOC (`archiveCache.ts`), +150 LOC (`archiveCache.test.ts`, 9 cases), ~25 LOC delta in `vite.config.ts` (handler shrinks, watcher widens). 82/82 tests passing (was 73; +9 from new cache tests). `tsc --noEmit` clean. Cold-start UX unchanged; warm-request UX drops from 1.26s/421ms (fintown/flowtron) to in-memory.
