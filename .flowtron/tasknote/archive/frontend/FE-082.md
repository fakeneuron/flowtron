**Discovery Notes:**

Root cause: `viz/src/ui/App.test.tsx` lines 55-56 assert `targetRow.className` synchronously, with no retry/poll window, immediately after an `await waitFor(...)` on a *different* effect (`scrollSpy`) that fires from the same `requestAnimationFrame` callback just before the `setHighlightId` call that drives the class. Every other timing-sensitive assertion in this test (lines 45-47, 51-53, 59-61) is wrapped in `waitFor`; this one isn't, making it the sole assertion with zero tolerance for the sub-tick gap between the mock call becoming observable and React's state commit landing in the DOM. FE-053 already maximized the two available timeout levers (`testTimeout` 15s, `asyncUtilTimeout` 5s) for this exact file in 2026-06 — a further timeout bump wouldn't help an assertion that isn't polling at all. Fix: wrap the assertion in `waitFor`, consistent with the surrounding pattern.
