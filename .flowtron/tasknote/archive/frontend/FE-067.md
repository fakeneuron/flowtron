**Discovery Notes:**

- All 4 reported lines are `[x]` completed, carry no `[model]`/`| shortname` segment, and their bold token doesn't match the AREA-NNN grammar at all (no dash-then-digits shape) — distinguishing them cleanly from a hand-authoring typo of a real ID (e.g. `**CORE-04X**` would still fail this legacy gate since... actually a typo'd real ID like `CORE-04X` also lacks `[model]`/`|shortname` in many hand-typed cases — the load-bearing distinguisher is the ID-shape check itself, not the missing `[model]`/`|shortname`, since those are optional on real lines too). Refined design: the legacy-exclusion path requires the bold token to look like free-text (contains a lowercase letter, a space, or fails to match even a loose `[A-Z]+-?\d` shape) — NOT simply "any string that isn't AREA-NNN". This keeps `**CORE-04X**` (plausible fat-finger of `CORE-041`) correctly landing in `unparsed` for a human to notice, while `**P1**`/`**flowtron v5.2.0 bump**` are excluded.

## 🛠️ Phase 2: Execution

- [x] **Pattern survey** — FE-066 added tolerances as non-capturing groups *inside* `TASK_LINE` because those cases are decorations on an otherwise-valid ID. This case is structurally different (the ID itself is absent), so it needed a sibling regex (`LEGACY_LABEL_LINE`) applied only inside the existing `CHECKBOX_BULLET`-then-`TASK_LINE`-fails diagnostics branch, rather than forcing it into `TASK_LINE` itself.

- [x] Implemented the minimal solution

- [x] Updated/added tests for non-trivial behavior

**Implementation Notes:**

`viz/src/parser.ts`: added `LEGACY_LABEL_LINE` (matches a bare `**token**` optionally followed by an em/en-dash description — no room for `[!critical]`/`[model]`/`| shortname`, so those still fall through to `unparsed`) and `ID_SHAPE_CASE_INSENSITIVE` (the discriminator: excludes only tokens with no letter-dash-digit ID structure at all, so a case-typo like `**fe-065**` still surfaces). In the diagnostics loop, a `CHECKBOX_BULLET`-matching line that fails `TASK_LINE` is now excluded from `unparsed` only when it also matches `LEGACY_LABEL_LINE`, is `[x]` completed, and its token fails `ID_SHAPE_CASE_INSENSITIVE`.

SPEC.md §"Task-line format": added a "Legacy label lines (excluded, not tolerated)" note distinguishing this exclusion from the decorative FE-066 tolerances.
