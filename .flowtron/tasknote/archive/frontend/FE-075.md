## 🎯 Goal

Anchor `extractSection`'s heading match in `viz/src/tasknote.ts` to a word boundary so `'Phase 1'` no longer matches a `'Phase 10'` heading and `'Goal'` no longer matches `'Goals'`.

## ⚡ Notes

**Relevance:** Proceed — the loose `includes()` match is still present at `viz/src/tasknote.ts:112`; fix is a single-function, single-file change with no design tradeoffs.
**Best Practices Review:** Single-responsibility change inside `extractSection`; no dependency-boundary or duplication concerns. Added a small local `escapeRegExp` helper (no existing one in `viz/src/`) rather than reaching for a dependency.
**Drift check:** `extractSection` at `viz/src/tasknote.ts:104` (originally cited as line ~104, unchanged) and the `includes()` call now at line 112 (was line 112 pre-fix too) — no drift from the PLAN.md citation.
**Archive skim:** Checked `archive/frontend/` for prior tasknotes touching `tasknote.ts`/`extractSection` (FE-002, FE-003, FE-004, FE-005, FE-006, FE-011, FE-012, FE-014, FE-016, FE-018, FE-024, FE-026, FE-028, FE-073) — none recorded findings about the loose substring match; no load-bearing prior context.
**Pattern survey:** Extended the existing single-function shape in `tasknote.ts`; no sibling pattern for regex-anchored heading matching existed to follow, so introduced a minimal word-boundary regex built per call (titles are short, cheap to compile) rather than a shared table.
**Implementation:** Replaced `heading[1].includes(titleSubstring)` with a `\b<title>\b` regex test (title escaped via a new local `escapeRegExp` helper) in `extractSection` (`viz/src/tasknote.ts:104-127`). Added a regression test in `viz/src/tasknote.test.ts` covering `'Phase 1'` vs `'Phase 10'` and `'Goal'` vs `'Goals'` heading collisions.
