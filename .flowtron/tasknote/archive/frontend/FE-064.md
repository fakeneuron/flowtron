# FE-064 | viz-render-resilience

[← PLAN.md](../PLAN.md) · 🟢 In progress · 🔗 [[FE-065]]

## 🎯 Goal

Harden the viz UI against malformed tasknote data and dropped live-refresh: a bad tasknote should degrade one row's detail panel instead of blanking the whole board, silent SSE loss should reconcile on reconnect, and the `vscode://` link path should be validated before interpolation.

## ✅ Acceptance

- [ ] A render error inside an expanded `TaskDetail` (e.g. malformed markdown) is caught by an `ErrorBoundary` and shows a small inline fallback — the rest of the board keeps rendering.
- [ ] The boundary wraps the per-row `TaskDetail` mount (TaskRow / EpicRow / SubtaskRow), not the whole-app root, so only the affected row's detail degrades.
- [ ] `useProjectData`'s `EventSource` has an error/reconnect handler so a dropped SSE connection reconciles missed changes on recovery rather than going silently stale.
- [ ] The `vscode://file` href in `TaskDetail` validates `tasknote.path` (absolute path) and encodes it before interpolating; an invalid path renders no broken link.
- [ ] `npm --prefix viz run lint` + `typecheck` clean; targeted tests for changed files pass.

## 🧩 Subtasks

- [ ] Add `viz/src/ui/ErrorBoundary.tsx` — minimal class component with a fallback render prop / node.
- [ ] Wrap the three `<TaskDetail>` mounts (TaskRow, EpicRow, SubtaskRow) in `<ErrorBoundary>` inside their existing `<Suspense>`.
- [ ] Add an `EventSource` `error`/`open` handler in `useProjectData` to reconcile after reconnect.
- [ ] Add a `vscode://` path guard + encode helper in `TaskDetail`.
- [ ] Add targeted tests (ErrorBoundary fallback; path validation).
- [ ] Lint + typecheck + targeted tests.

**Discovery Notes:**

**Render tree.** `TaskDetail` (which renders `WikilinkMarkdown` on `task.description`, and `DetailSection` on tasknote markdown) is lazy-imported and mounted at **three** sites, each already wrapped in `<Suspense fallback={null}>`: `TaskRow.tsx:55`, `EpicRow.tsx:114`, `SubtaskRow.tsx:79`. This is the only place malformed tasknote markdown reaches React render.

**⚠️ Drift — ErrorBoundary location.** The task cites `viz/src/ui/App.tsx:268` (the whole-app `return (`). Wrapping an `ErrorBoundary` there would blank the **entire board** on one malformed tasknote — the opposite of the stated goal ("degrades one row instead of blanking the whole board"). To meet the goal the boundary must sit at the **per-row** seam, wrapping each `<TaskDetail>` mount (TaskRow / EpicRow / SubtaskRow). Corrected plan edits those three files + a new `ErrorBoundary.tsx` instead of App.tsx.

**No existing pattern.** `grep` finds no `ErrorBoundary` / `componentDidCatch` / `getDerivedStateFromError` in `viz/src` — a new (class) component is required (React error boundaries cannot be function components). Justified new shape.

**SSE handler (useProjectData:64-68).** `EventSource` currently listens only for `change`. On a dropped connection the browser auto-reconnects but any changes emitted during the gap are missed — the board silently goes stale. Plan: add an `open` listener that calls `refresh()` (reconciles missed changes on every (re)connect; the redundant refresh right after initial load is harmless) plus an `error` listener for observability. Stays inside the task.

**vscode:// path (TaskDetail:51).** `tasknote.path` is a server-provided filesystem path (`parseTasknote(id, path, text)`). Interpolated raw into `vscode://file${path}`. Plan: only render the anchor when the path is an absolute POSIX path, and `encodeURI` it. Defensive; stays inside the task.

**Gate judgment:** Discovery surfaced a significant deviation (ErrorBoundary edit target moves from App.tsx to three row components + new file) → fire 🛠️.

- [x] **Pattern survey** — no existing error boundary in `viz/src`; the three `<TaskDetail>` mounts share an identical `<Suspense fallback={null}>` shape, so the new `<ErrorBoundary>` wraps each of them consistently. React error boundaries must be class components → justified new shape.

**Implementation Notes:**

- New `viz/src/ui/ErrorBoundary.tsx` — minimal class boundary, `getDerivedStateFromError` + `componentDidCatch` (console.error), default muted fallback, overridable via `fallback` prop.
- Wrapped the three `<TaskDetail>` mounts in `<ErrorBoundary>` **outside** the existing `<Suspense>` (catches both lazy-chunk load failures and render throws): `TaskRow.tsx`, `EpicRow.tsx`, `SubtaskRow.tsx`.
- `useProjectData.ts` — added `open`/`error` `EventSource` listeners; a drop flags `droppedSinceOpen`, and the next `open` calls `refresh()` to reconcile missed changes. First connect does not refresh (no prior drop) → no redundant initial fetch.
- `TaskDetail.tsx` — exported `vscodeFileHref(path)` helper: returns `vscode://file` + `encodeURI(path)` only for an absolute POSIX path, else `null`; anchor now gates on `vscodeHref` so an invalid path renders no link.
