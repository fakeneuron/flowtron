### Failure mode rationale (why A1 vs A2)

`load()` has two callers:
1. `useEffect` on `activeProject` change (line 110) — project switch path
2. `refresh()` via SSE `'change'` event (line 113-116) — file-save refresh path

The reported Frankenstein view is exclusively a *switch-path* problem: new title (from `activeProject`) over old rows (from un-cleared `tasks`). On the SSE-refresh path, `activeProject` doesn't change, so there's no title-vs-rows mismatch — if the refresh fails, the user sees the same data they had a moment ago, which is recoverable on the next save.

Pre-clearing at top of `load()` (option A2) would correctly fix the switch case but would also wipe-and-reload on every SSE refresh, causing an unnecessary empty-state flash on each tasknote save. A1 scopes the clear to the switch path where the bug actually lives.

### Out of scope

- **Independent per-endpoint fetches (option B)**: rejected by user lock. Real UX design call (multi-error banner shape, partial-render semantics, header count behavior during slow-laggard) and FE-029 already eliminated the dominant upstream trigger. Defer until/unless partial-load UX becomes a felt need.
- **SSE-refresh failure UX**: not the surfaced bug. If a refresh fails, current behavior (keep old data + show error banner) is acceptable since `activeProject` hasn't changed.
- **`/api/projects` failure handling**: the project-list fetch (line 89) already has its own error path setting `error`; FE-030 is scoped to `load()` only.
- **Per-endpoint error attribution in the banner**: would require option B's structural change. The current single-string error banner is sufficient.

**Implementation Notes:**

### Pattern survey

The fix is split across two surfaces: a state-reset addition in `App.tsx` and a test-scaffold extension in `fixtures.ts`.

- **`App.tsx:handleSelectProject` (line 238-251)** — already a flat block of resets (`setQuery('')`, `setTagFilter(new Set())`, `setStatusFilter(new Set())`, `setExpandedId(null)`, `setExpandedEpicIds(new Set())`, `setSelectedId(null)`, `setCollapsedSections(new Set(['Completed']))`, timer cleanup, scroll-to-top, `setActiveProject(name)`). Pattern: enumerate every piece of UI state that should be reset on project switch. `setTasks([])` + `setTasknotesById(new Map())` slot into that pattern as two more resets, batched into the same React 18 setter group so the next render is consistent.
- **`fixtures.ts:seedFetch`** — existing shape is a single fetch mock that treats all projects identically (the `?project=<name>` query was stripped via `raw.split('?')[0]`). The minimal extension was to switch the path parser to `new URL(raw, 'http://localhost')` so we can read `searchParams.get('project')`, then layer a `perProject` override map on top. Default behavior is unchanged when `perProject` is absent.
- **`App.test.tsx`** — new describe block mirrors the existing `App — project switching` shape (line 239): two-project setup, `beforeEach(() => window.localStorage.clear())`, `user.click` on the project chip, `waitFor` assertions on heading/error.

### Files changed

- **`viz/src/ui/App.tsx`** (+2 LOC): added `setTasks([])` and `setTasknotesById(new Map())` inside `handleSelectProject` between `setCollapsedSections(new Set(['Completed']))` and the highlight-timer cleanup. Position chosen to keep all `set<X>` calls grouped before the side-effect/timer block.
- **`viz/src/test/fixtures.ts`** (+~15 LOC): added `ProjectFetchOverride` interface (`plan?`, `active?`, `archive?`, `fail?`); added `perProject?` to `FetchSeed`; rewrote `seedFetch` to parse the URL via `new URL(raw, 'http://localhost')`, route by `project` query param, and respect per-project `fail` codes / data overrides. Default flat-shape behavior preserved.
- **`viz/src/ui/App.test.tsx`** (+~40 LOC): new `App — load() partial failure on project switch` describe block with one `it` that proves the stale-state bug is fixed.

### Design decisions

- **Clear in `handleSelectProject`, not in `load()`**: `load()` is also called by the SSE `'change'` event handler (`refresh()`, line 113-116). Pre-clearing at the top of `load()` would cause an empty-state flash on every file save. Scoping the clear to the switch path leaves the SSE-refresh UX unchanged. User-locked at Discovery.
- **`new URL(raw, 'http://localhost')` for path/query parsing in fixtures**: simpler than manual `indexOf('?')` slicing; provides `pathname` and `searchParams` cleanly. The base URL is a harmless placeholder — viz fetches are all relative.
- **`perProject` override structure**: each project's overrides cascade with the top-level defaults, so common-case tests stay terse (just pass top-level `plan`/`active`) and failure tests opt in only on the projects that diverge.
- **Test asserts "row not in DOM" rather than "tasks state is empty"**: end-to-end semantic — the actual symptom in FE-020 was a row visible under the wrong title. Asserting on render output catches both the state-clearing fix and any future regression where the state is cleared but rendering somehow lags.
- **No fintown plan distinction needed in the test**: archive failure throws before `setTasks` would have run, so fintown's plan never reaches the DOM regardless. The test's discriminator is "`CORE-100` (from flowtron) is gone", which holds under all three meaningful states (cleared and load-failed, cleared and load-succeeded, never-loaded).
