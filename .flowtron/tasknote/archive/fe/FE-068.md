# FE-068 | project-switcher-tab-overflow

[← PLAN.md](../PLAN.md) · 🟢 In progress

## 🎯 Goal

Fix the multi-project switcher's tab bar so it no longer overflows or gets visually cut off once enough project tabs are open — add wrap or an alternate layout (dropdown/scroll) at high tab counts.

## ✅ Acceptance

- [ ] `ProjectSelector` shows at most `MAX_VISIBLE` project buttons inline as the existing segmented control; the rest collapse behind a trailing "+N" toggle button
- [ ] If the active project would otherwise fall in the overflow set, it is pinned into the visible set (swapped in for the last visible slot) so the current selection is always shown without opening the dropdown
- [ ] Clicking "+N" opens a dropdown panel listing the overflow projects as selectable buttons (same `onSelect`/`aria-pressed` semantics as the inline buttons); selecting one calls `onSelect` and closes the panel
- [ ] Dropdown dismisses on outside click and on Escape
- [ ] Existing aria contract preserved for all buttons (`aria-pressed`, `aria-label="Project: <name>..."`, version-currency dot)
- [ ] `ProjectSelector.test.tsx` covers: no overflow button below threshold; overflow button appears above threshold; active project pinned visible when originally beyond threshold; dropdown open/select/close (outside-click + Escape)
- [ ] `npm test` + `npm run typecheck` clean in `viz/`
- [ ] Visual confirmation accepted by user (👁️)

## 🧩 Subtasks

- [ ] Add a colocated `MAX_VISIBLE` constant to `ProjectSelector.tsx` (mirrors `RelatedChip.tsx`'s `MAX_VISIBLE` convention) and partition `projects` into `visible` / `overflow`, pinning `active` into `visible` if it would otherwise overflow
- [ ] Render `visible` as the existing segmented buttons, recomputing corner/divider classes against the new (possibly-reordered) index set
- [ ] When `overflow.length > 0`, append a trailing "+N" toggle button as the last segment (`rounded-r`), with `aria-haspopup="true"` / `aria-expanded={open}`, toggling local `open` state
- [ ] Render an absolutely-positioned dropdown panel below the toggle when `open`, listing `overflow` projects as buttons with the same select/active/currency-dot rendering as inline buttons; style to match the tab bar's own container language (`rounded border border-slate-300 bg-white shadow-sm dark:border-slate-700 dark:bg-slate-900`) rather than the heavier `SettingsModal`/`ShortcutsModal` centered-dialog styling
- [ ] Wire dismissal: `mousedown` outside-the-component listener + `Escape` keydown listener via `useEffect` while `open`; also close on item selection
- [ ] Update/add `ProjectSelector.test.tsx` cases per the Acceptance list
- [ ] Run `npm test` + `npm run typecheck` in `viz/`; request visual confirmation (👁️)

**Implementation Notes:**

- **`ProjectSelector.tsx`** (71 → 143 lines). Added `MAX_VISIBLE = 5` (colocated, mirrors `RelatedChip.tsx`). `projects` is partitioned into `visible`/`overflow`: normally the first `MAX_VISIBLE`; if `active` sits at or past that boundary, it's swapped into the last visible slot (displacing that slot's project into `overflow`) so the current selection is never hidden. Extracted the per-chip render (button + version-currency dot) into a local `renderChip(name, corner, divider)` helper, reused for both the inline segmented row and the dropdown panel's rows (dropdown chips pass `''`/`''` for corner/divider — no rounding/divider makes sense in a vertical stack). When `overflow.length > 0`, a trailing `+N` toggle (`aria-haspopup="true"`, `aria-expanded`) is appended as the segmented group's final (`rounded-r`) segment; clicking it toggles a local `open` state that renders an absolutely-positioned `role="menu"` panel below, styled to match the tab bar's own border/shadow language. A `useEffect` (only wired while `open`) adds document-level `mousedown` (outside-click) and `keydown` (`Escape`) listeners to dismiss; selecting any chip (visible or overflow) also closes the panel.
- **`ProjectSelector.test.tsx`** — 5 new cases: no toggle at/below threshold; toggle + hidden entries above threshold; active-project pinning when it would otherwise overflow; open → select-from-menu → `onSelect` called + menu closes; Escape and outside-click both dismiss the open menu. All existing cases pass unchanged (aria contract, empty-list, currency dots untouched).
- **Scope discipline** — no arrow-key nav between chips (none existed before either), no tab reordering/persistence, no per-project close affordance — all flagged out of scope in Discovery.
