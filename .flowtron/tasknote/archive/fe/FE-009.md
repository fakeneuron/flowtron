**Implementation Notes:**

- **Pattern survey.** No existing module owns global UI state in `viz/src/ui/` — `App.tsx` holds all task-state via `useState`/`useCallback`/`useEffect` and each leaf component is a self-contained `React.FC`. `ThemeToggle` follows that shape: local `useState` for the preference, a `useEffect` that calls `applyResolved` and (when in `system`) subscribes to `matchMedia` change events. The new `theme.ts` mirrors the placement style of `utils.ts` and `constants.ts` (small typed module beside the components). The pre-React init script in `index.html` has no precedent in this repo — flagged as a justified new shape (canonical Tailwind no-FOUC pattern; running it in `main.tsx` would race against the bundle parse and produce a brief flash of wrong theme on cold load).
- **`tailwind.config.ts`.** Added `darkMode: 'class'`. Theme.extend stays empty — every dark variant is expressed as a `dark:` utility class, no custom CSS variables needed.
- **`index.html`.** Synchronous `<script>` block inserted in `<head>` after the favicon link. Reads `localStorage.theme`; `dark` if stored value is `'dark'` OR (stored is not `'light'` AND `prefers-color-scheme: dark` matches). Adds `dark` class to `documentElement` if dark. Wrapped in try/catch so localStorage failures (private mode, etc.) silently fall through to OS pref. Runs before the `/src/main.tsx` module script tag, so the class is set before React's first paint.
- **`src/ui/theme.ts` (new, 36 lines).** Exports `ThemePreference` type and four helpers: `readPreference()` reads the storage key (returns `'system'` for absent/invalid); `writePreference(pref)` removes the key for `'system'`, sets it for the other two; `resolvePreference(pref)` collapses `'system'` to a concrete `'light' | 'dark'` via matchMedia; `applyResolved(pref)` resolves and toggles the `dark` class on `documentElement`; `subscribeSystem(cb)` attaches a `change` listener to the matchMedia and returns the disposer. All localStorage access wrapped in try/catch.
- **`src/ui/ThemeToggle.tsx` (new, ~45 lines).** `useState` initialized from `readPreference()`. `useEffect` runs `applyResolved(pref)` on every change, and (only when `pref === 'system'`) subscribes to `subscribeSystem(() => applyResolved('system'))` so a live OS-theme change reflects without reload; the cleanup tears the subscription down on transition out of `system`. Click handler advances state through the `NEXT` map (`light → dark → system → light`), writes to localStorage, sets the new state. Button styling matches the Refresh button (same border/bg/padding) so the header right cluster reads as one row of three controls.
- **`App.tsx` wiring.** Imported `ThemeToggle`, rendered after the Refresh button in the header right cluster. Added `dark:` variants to: page container (`dark:bg-slate-950 dark:text-slate-100`), header (`dark:border-slate-800 dark:bg-slate-900`), task-count line, search input (placeholder + focus ring), Refresh button, error banner, and both filter rails — Tags + Status. Filter chip on-state inverts cleanly (`dark:bg-slate-200 dark:text-slate-900`); off-state status chips inherit the new `STATUS_BADGE` table from `constants.ts`.
- **Chip palette inversion.** Adopted the Tailwind canon: light `*-100/*-800` → dark `*-950/*-200`. Applied uniformly to STATUS_BADGE (5 entries in `constants.ts`), PRIORITY_BADGE (6 entries in `TaskDetail.tsx`), due-label variants (amber/red/indigo in `TaskRowInner.tsx`), BlockerChip (rose), filter chip off-state (slate), tag chip (slate), epic done-counter chip (slate). Section tints in `PrioritySection.tsx` use a softer `dark:bg-{color}-950/30 dark:border-{color}-900` so the section frames stay subtle in dark mode rather than competing with the rows inside.
- **Highlight ring.** `border-amber-400 ring-amber-300` in `TaskRow`/`EpicRow` paired with `dark:border-amber-500 dark:ring-amber-600` so the navigation highlight stays visible against the dark slate row bg. SubtaskRow highlight uses `dark:bg-amber-900/30 dark:ring-amber-700` (the looser `/30` opacity reads as a tinted overlay rather than an opaque chip).
- **Leaf chips.** Eight files touched at the leaf level (`Chevron`, `BlockerChip`, `RelatedChip`, `ModelChip`, `PhaseDots`, `SubtaskProgress`, `WikilinkMarkdown`, plus the `StatusChip` indirectly via the `STATUS_BADGE` table). PhaseDots: emerald and amber stay the same (strong colors read fine on either bg); inactive `bg-slate-200` → `dark:bg-slate-700`; active dot's `ring-amber-200` → `dark:ring-amber-700`. SubtaskProgress: track `bg-slate-200` → `dark:bg-slate-800`; the sky-500 fill stays.

Adding a single ThemeToggle test now would require setting up the testing harness ahead of FE-014 and would duplicate that task's scaffold work — same justification used in FE-008.
