### Finding — one real miss, escaping three closures

**`viz/vite.config.ts:80` passes a one-shot iterator where the handler needs a
re-iterable.** `createOnWatchEvent({ projects: projects.values(), … })` hands in
a `Map` iterator. The handler (`viz/src/flowtronWatch.ts:134-146`) iterates
`opts.projects` **twice per event** — once via `archiveCache.invalidate()`
(`viz/src/archiveCache.ts:69-77`) and again via `projectForPath()` — and the
handler is reused for **every** event on both watchers.

Consequence, first event onward: for a `PLAN.md` change, `invalidate()` walks the
iterator to exhaustion without matching (a `PLAN.md` path is not under any
`archiveDir`), so `projectForPath()` receives a dead iterator and
`broadcast.schedule()` is called with `undefined` — [[FE-088.3]]'s SSE project
attribution never works. From the second event on, the iterator is dead for
`invalidate()` too, so archive-cache invalidation silently stops matching
entirely.

**Why three test-green closures missed it:** every test constructs the handler
with `projects: [alpha]` — an **array**, which is re-iterable. The parameter is
typed `Iterable<ProjectDescriptor>`, which both satisfy, so the production
call site and the test call site differ in exactly the property that matters
and the type system cannot tell them apart. 391 passing tests are structurally
incapable of catching this.

**Not a cohort defect.** `.2` identified it as *pre-existing*, surfaced
incidentally while working nearby, and correctly declined to fold an unrelated
behavior fix into a dependency bump. `.3` and `.4` each re-confirmed it present
and identical to baseline. The failure is not the deferral — it is that all
three Final Summaries flag it as **"still unfiled in PLAN.md"** and no closure
converted that observation into a PLAN line. It survived three separate Phase 4
sweeps as a note about itself. This audit files it.

**Filed as standalone, not as `FE-090.5`.** The epic's theme is "viz major-bump
wave"; an SSE-attribution/iterator bug predates the wave and belongs to none of
its children. Filing it as a fourth child would stretch the epic to hold
unrelated work and block the parent flip on it. It also needs a regression test
that specifically passes a one-shot iterator — real work with its own gate run,
above the inline-audit-fix threshold this skill sets ("a stale path reference"),
so it is filed forward rather than patched here.
