# FE-94.3 | Lift App's derived selectors into a pure taskView module

[← PLAN.md](../PLAN.md) · 🟢 In progress · 🔗 [[FE-EPIC-94]] [[FE-94.2]] [[FE-94.4]]

## 🎯 Goal

Move `App.tsx`'s seven inline view-model derivations — `matchesFilter`, the child-pruning `filteredNodes`, `bySection`'s critical-first sort, `listViewEmptySections`, `epicIds`, `visibleIds`, and the three count reducers — into a new pure `viz/src/ui/taskView.ts` with direct unit tests, leaving every `useMemo`/`useCallback` boundary and dependency array in `App.tsx` exactly where it is.

## ✅ Acceptance

- [x] `viz/src/ui/taskView.ts` exports the extracted selectors as plain functions — no React import, no hooks, no closure over component state
- [x] `viz/src/ui/taskView.test.ts` covers the semantics the DOM tests can only assert indirectly: parent-kept-when-child-matches with non-matching siblings pruned, the `filteredCount` identity (`1 + children.length` summed), critical-first stable sort within `High`, `visibleIds` order across collapsed sections and collapsed epics, `effectiveStatus` fallback in the in-progress count
- [x] `App.tsx` keeps every `useMemo`/`useCallback` wrapper and dependency array unchanged — memoization boundaries do not move in this child
- [x] Behavior-preserving: no feature change; `App`'s public surface (props-less `React.FC`) unchanged
- [x] FE-94.2's characterization tests plus the whole existing viz suite green before the move and unchanged after it
- [x] `npm --prefix viz test`, `npm --prefix viz run typecheck`, and `npm --prefix viz run lint` all green

The starter's locked decision to use a *new* `taskView.ts` rather than growing `utils.ts` holds up on inspection: `utils.ts` is a grab-bag of six unrelated single-purpose helpers, while these nine functions form one cohesive view-model pipeline (`matchesFilter` → prune → group → visible ids/counts).
