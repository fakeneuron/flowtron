**Best Practices Review.** Touched responsibilities split cleanly along FE-093's tiers: heading grammar + concatenation is shared-pure (`parser.ts`); reading the file off disk is Node-only (`workspace.ts` + `devApi.ts` + the `vite.config.ts` mount); fetching and wiring is browser UI (`useProjectData.ts`). Existing abstractions extended rather than invented: `LEGACY_CRITICAL_HEADING`'s branch shape for the heading, `createPlanHandler`'s guard/containment shape for the endpoint, `useProjectData`'s existing `Promise.all` fan-out for the fetch. Nearby duplication: the scan loop is used twice now, so it is extracted to one private scanner rather than copied. Deferred: no `watchSet.ts` change (see below); no eslint tier enforcement (FE-093's deferral, untouched).

**Design decisions.**
1. **Separate `/api/plan-archive` endpoint, not a concatenated `/api/plan` body.** Server-side concatenation would need no client change and no new route, but it would make `unparsed.line` point at a line number that exists in neither file, breaking the FE-063.2 contract that `App.tsx` renders verbatim. Two documents stay two documents.
2. **Diagnostics stay `PLAN.md`-only.** The archive is machine-rotated, verbatim, append-only, and never hand-authored, so it is not the surface FE-063.2's diagnostics were built for — and reporting an archive line number under a "lines in PLAN.md" banner would be actively misleading. Alternative considered and rejected as beyond scope: adding a `file` field to `UnparsedLine` / `NearMissHeading` and threading it through the banner UI.
3. **Absence is 200-with-empty-body, never 500.** The contract says absence is an empty archive; beyond that, an optional history file must never be able to fail the whole board, so the client also degrades a non-ok response to an empty archive.
4. **The month heading is recognized everywhere, not only in archive input.** One scanner, no mode flag — a `## Completed <YYYY-MM>` heading in `PLAN.md` would be unusual but harmless, and a mode flag would buy nothing.
5. **No `watchSet.ts` change.** Rotation is the only writer, and it always edits `PLAN.md` (rows leave) in the same motion, so the existing hot watch on `planPath` already fires an SSE change that refetches both files. Watching an append-only file that never changes alone would be cost without benefit.

**No clarifications needed.** Explicit assumptions: (1) the route name is `/api/plan-archive`; (2) rotated rows need no grammar change because rotation moves them verbatim; (3) archive tasks are appended after `PLAN.md` tasks, and `groupTasks` handles any epic parent/child split across the two files by its existing key index; (4) `CORE-470` owns the `/ft-stats` half of the same contract and is out of scope here.

**Implementation Notes:**

**Pattern survey.** Every piece extends an existing shape rather than inventing one. The heading rule copies `LEGACY_CRITICAL_HEADING`'s branch (FE-044): map a non-canonical heading onto a canonical `Priority` inside the heading branch, leaving `SECTION_HEADINGS` as the five names the board renders. `createPlanArchiveHandler` copies `createPlanHandler`'s guard order and `createActiveHandler`'s `safeRealpath` root + `realpathWithin` containment. The fourth fetch joins `useProjectData`'s existing `Promise.all` fan-out.

**Minimal refactor gate.** One refactor, required by Acceptance: the scan loop now runs over two documents, so its body moved into a private `scanDocument()` and `parsePlanWithDiagnostics` became a thin wrapper over it. Copying the loop would have been the duplication the gate exists to prevent. Nothing else in `parser.ts` moved — the grammar fragments, `groupTasks`, and every exported type are untouched.

**Implemented (5 source files + `vite.config.ts`).**
- `parser.ts` — `COMPLETED_MONTH_HEADING` (`/^Completed\s+\d{4}-\d{2}$/`) mapped to `'Completed'` in the heading branch; loop body extracted to private `scanDocument()`; `parsePlanWithDiagnostics(markdown, archiveMarkdown?)` concatenates `tasks` and keeps `plan`'s diagnostics via `{ ...plan, tasks: [...] }`.
- `workspace.ts` — `ProjectDescriptor.planArchivePath`, set unconditionally in `discoverProjects` (absence is normal, so it is not a discovery gate).
- `devApi.ts` — `createPlanArchiveHandler`: same method/origin/project guards, then `safeRealpath(project.root)` + `realpathWithin`. A null from either (missing **or** escaping) and a `readFile` throw all answer 200 with an empty body; only the read failure logs.
- `vite.config.ts` — mounts `/api/plan-archive`. Connect matches mount paths on a `/` or `.` boundary, so `/api/plan` does not swallow it.
- `useProjectData.ts` — fourth parallel fetch; unlike the other three it never throws (`planArchiveRes.ok ? await .text() : ''`), then feeds the parser.
- No `watchSet.ts` change, per the Discovery decision.

**Tests (4 files).** `parser.test.ts` +8 (month heading incl. nested children, malformed `YYYY-MM-DD` heading stays unrecognized, near-miss suppression, ordering, absent-archive equivalence, diagnostics scoping, cross-file epic grouping). `devApi.test.ts` +6 (present / absent / symlink-escape / 400 / 403 / 405), and its `makeProject` helper gained an opt-in `planArchiveText` so the *default* fixture is a never-rotated project. `useProjectData.test.ts` +3, plus the mock repair below. `workspace.test.ts` / `archiveCache.test.ts` / `watchSet.test.ts` / `flowtronWatch.test.ts` descriptor literals gained the new field — `workspace.test.ts`'s `toEqual` is what asserts `discoverProjects` sets it.
