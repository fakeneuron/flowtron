# FE-047 | viz-api-error-path-leak

[← PLAN.md](../PLAN.md) · 🟢 In progress

## 🎯 Goal

Stop echoing fs `error.message` (absolute home-dir paths) in `/api/*` error bodies in `viz/src/devApi.ts`; log server-side and return generic text — or document as accepted in `SECURITY.md`'s viz threat model.

## ⚡ Notes

**Relevance:** Proceed — single-file, mechanical hygiene fix (remove raw fs `error.message` from 3x 500 responses in devApi.ts); matches existing "log-to-stderr + generic client text" pattern already used in archiveCache.ts:readArchive and originGuard; no design tradeoffs, fits micro threshold exactly; "document as accepted" alternative rejected in favor of the trivial fix.
**Drift check:** no drift — viz/src/devApi.ts:59-62 (plan), 90-93 (active), 113-116 (archive) exactly match the cited `/api/*` catch blocks that do `res.end(\`...\${(e as Error).message}\`)`; the three fs-using handlers (readFile, safeReaddir via archiveCache, readdir) are unchanged since the audit finding.
**Archive skim:** prior FE tasknotes (FE-016/028/029/030/046) document the /api/* error paths and the convention of logging raw `(err as Error).message` to `console.error` (server stderr) while shielding the HTTP client; none touched devApi.ts's top-level handler 500 bodies specifically for this leak. No conflicting prior decisions on path disclosure in viz error responses. (See FE-029 for the per-file tolerant logging precedent.)
**Pattern survey:** neighboring code already follows the target shape: archiveCache.ts:30-34 does `console.error(\`[archiveCache] failed...\${message}\`)` then drops the row (no leak to caller); originGuard.ts returns only fixed generic strings like 'Forbidden: ...' on 403s. The three 500 sites in devApi.ts were the only remaining spots echoing raw fs .message on the wire. Fix: add matching console.error + strip the `: ${message}` suffix from the three res.end() strings.
**Implementation:** 3 identical catch sites in `viz/src/devApi.ts` (createPlanHandler, createActiveHandler, createArchiveHandler) updated: raw `(e as Error).message` (fs paths) now only goes to `console.error('[devApi] ...')` on server stderr; HTTP 500 body is now a short generic string with no path info. ~9 LOC net (3 logs + 3 string trims). No test updates needed (no assertions on 500 bodies existed). Aligns with archiveCache + originGuard precedent.
**Docs touched:** no change (SECURITY.md viz section already scopes the dev server as localhost-only single-user tool; the fix removes a minor info leak without requiring doc updates).

## ✅ Recap

Fixed info-leak in viz dev API: the three 500 catch blocks in `viz/src/devApi.ts` (createPlanHandler, createActiveHandler, createArchiveHandler) no longer echo raw fs `error.message` (absolute home-dir paths from readFile/readdir failures) into HTTP response bodies. Full diagnostic now only on server stderr via `console.error('[devApi] ...')`; responses are short generics ("Failed to read PLAN.md" etc.). ~9 LOC, pattern-matched to archiveCache.ts + originGuard.ts.
