### Pre-write hypothesis (to be validated in Phase 2)

Six candidate workstreams likely surface; each at a different magnitude:

1. **Chip family unification** — 5 chip files (BackRef/Blocker/Model/Related/Status, ~64 LOC combined) share near-identical Tailwind class shape but with intentional tone/variant differences. Real duplication, but ROI is moderate — collapsing to one `<Chip>` primitive would risk premature abstraction. Need user judgment on tradeoff.
2. **`STATUS_LABEL` ↔ `STATUS_CHIP_LABEL` co-location** — two divergent maps in two files (`constants.ts`, `StatusChip.tsx`); same key set, different values (with/without emojis). Bug risk: add a new status to one but not the other → silent drift. Easy fix: co-locate both in `constants.ts`.
3. **ID-prefix regex restated across files** — `[A-Z]+(?:-EPIC)?-\d+(?:\.\d+)?` and its variants appear in `parser.ts` (5 sites), `App.tsx` (2 sites), `PrioritySection.tsx` (1 site), `WikilinkMarkdown.tsx` (1 site). `subtaskParentKey` and `epicKey` exist as private helpers in `parser.ts` but aren't exported, so callers re-roll the regex. Easy fix: export `isEpicId(id)` + `getSubtaskParentKey(id)` from `parser.ts`.
4. **Active/default pill pattern restated in 3 sites** — App.tsx tag rail, App.tsx status rail (partial), `ProjectSelector.tsx`. Same Tailwind class string `'bg-slate-800 text-white dark:bg-slate-200 dark:text-slate-900'` (active) vs slate-toned default. Extract `<FilterPill>` shared component or `pillClass(active)` helper.
5. **Highlight/select ring class restated in EpicRow ↔ TaskRow** — both ship the same ~6-line conditional ring-class string for `highlightId === task.id` / `selectedId === task.id` / default. Extract `rowOutlineClass()` helper. SubtaskRow has a similar but narrower variant.
6. **App.tsx orchestrator decomposition** — 465 LOC. Could extract `<Header>` (header + filter rails ~90 LOC), `useToggleSet<T>()` hook (4 toggle helpers share pattern), and `projectStorage.ts` (localStorage helpers). Improves readability; not a duplication fix per se.
