**Discovery Notes:**

**Duplication 1 — expandable detail wrapper.** All three rows end with the same nine-line block, differing only in the expanded-id expression, the tasknote lookup, and SubtaskRow's `compact` flag:

```tsx
{expandedId === task.id && (
  <ErrorBoundary>
    <Suspense fallback={null}>
      <TaskDetail task={...} tasknote={...} detailSections={visibility.detailSections}
        starterSections={visibility.starterSections} navigateToTask={navigateToTask} />
    </Suspense>
  </ErrorBoundary>
)}
```

Every prop is derived from two contexts (`useRowInteraction`, `useVisibilityPrefs`) that the panel can read itself, so the extracted component needs only `task` and an optional `compact`. `expandedId` comes from the same context, so the panel can own the conditional too — leaving each row with a single `<TaskDetailPanel task={task} />` line.

**Duplication 2 — outline class.** Three variants of one three-branch decision, differing only in which palette tokens they select:

| variant | highlighted | selected | neutral |
| --- | --- | --- | --- |
| task | `ROW_HIGHLIGHT` | `ROW_SELECTION` | `ROW_NEUTRAL` |
| epic | `ROW_HIGHLIGHT` | `ROW_SELECTION` | `EPIC_ROW_NEUTRAL` |
| subtask | `ROW_HIGHLIGHT_SUBTASK` | `ROW_SELECTION_SUBTASK` | *(hardcoded hover string)* |

The subtask neutral is the only one not modeled as a palette token — that asymmetry *is* the staleness the task names. Adding `ROW_NEUTRAL_SUBTASK` (same `_SUBTASK` suffix convention as its two siblings) with the current string verbatim in all three palettes makes the parameterization uniform at zero behavior change.

**Design.** `utils.ts` is the established home for pure viz helpers (`groupBy`, `effectiveStatus`, `versionCurrency`, `splitHighlight`) — extending `rowOutlineClass` there continues the FE-021 precedent rather than introducing a shape. `TaskDetailPanel.tsx` follows the one-component-per-file convention already used by `TaskRowInner` / `ClosureDriftChip` / `ErrorBoundary`. Dependency direction stays inward (rows → panel → TaskDetail); no new coupling. `SubtaskRow` keeps its own `tasknotesById.get(task.id)` because it also feeds the `ClosureDriftChip`; `TaskRow` and `EpicRow` drop `tasknotesById` and `navigateToTask` from their context destructures entirely.

**Boundary isolation preserved.** FE-064 deliberately placed the `ErrorBoundary` at the per-row seam rather than app-root. Extracting the block into a component that each row still renders *once per row* keeps one boundary instance per row — the isolation is a property of where the element is rendered, not where the JSX is authored.
