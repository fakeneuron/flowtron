**Discovery Notes:**

**The gap.** `createPlanHandler` (`viz/src/devApi.ts:78-99`) is the only one of the three project-scoped file-read handlers (`/api/plan`, `/api/plan-archive`, `/api/active`) that reads its target path with no per-request containment check. `project.planPath` (`viz/src/workspace.ts:92`, `join(projectRoot, '.flowtron', 'PLAN.md')`) is validated against `realpathWithin(realRoot, planPath)` only once, during `discoverProjects` at server startup/rescan. Between that scan and any individual `/api/plan?project=<name>` request, nothing re-checks that `planPath` still resolves inside the project root — so if `.flowtron/PLAN.md` (or an ancestor directory) is replaced with a symlink after discovery, the handler will happily `readFile` whatever it now points to and serve it as plain text.

**Pattern to mirror.** `createPlanArchiveHandler` (`viz/src/devApi.ts:110-142`) is the closest sibling: `safeRealpath(project.root)` → early-return on `null` → `realpathWithin(realRoot, project.planArchivePath)` → early-return on `null` → `readFile`. The only difference for `/api/plan` is the failure response: plan-archive degrades to an empty body (optional resource, FE-094 contract), plan does not (mandatory resource, existing 500 contract per the current test suite).
