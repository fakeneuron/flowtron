# FE-104 | node-tier-contained-read-dedup

[← PLAN.md](../PLAN.md) · ✅ Completed · 🔗 [[FE-088.2]]

## 🎯 Goal

Collapse the two byte-equivalent "contained tasknote directory read" loops in
`devApi.createActiveHandler` and `archiveCache.readArchive` into one shared
Node-tier helper, and wrap the three-line security prelude repeated across all
six `devApi.ts` handlers in a `guarded()` combinator so it cannot be omitted.

## ✅ Acceptance

- [x] A single Node-tier helper performs the `safeReaddir` → filter `.md` →
      `realpathWithin` → `readFile` → `parseTasknote` → drop-on-failure loop, and
      both `devApi.createActiveHandler` and `archiveCache.readArchive` call it
      instead of carrying their own copy
- [x] The helper lives in a leaf module both callers import, so no
      `archiveCache` ↔ `devApi` edge is created (the objection [[FE-088.2]]
      logged when it deferred this extraction)
- [x] Containment semantics are unchanged: the base is the project root resolved
      through symlinks, an escaping or unresolvable path drops that row
      silently, and an unreadable/malformed file drops that row without failing
      the whole listing
- [x] `applyApiHeaders` + `methodGuard` + `originGuard` are applied by one
      `guarded()` wrapper used by all six `devApi.ts` handlers; no handler body
      repeats the prelude
- [x] `viz/README.md` §Architecture reflects the new Node-only module (layout
      sketch + the `src/ui/` no-Node-import rule's module list)
- [x] `npm --prefix viz test`, `run typecheck`, and `run lint` all pass with no
      test-file edits required for the dedup itself (behavior is unchanged)

**The two duplications, confirmed at HEAD.**

1. *Contained read loop* (Finding #3). `devApi.ts:181-203` and
   `archiveCache.ts:20-41` run the same six steps — `safeReaddir(dir)` → keep
   `.md` files → `id` from the filename → `join` the path → `realpathWithin(realRoot, path)`
   → `null` ⇒ drop → `readFile` + `parseTasknote` inside `try`, `catch` ⇒ drop —
   then filter out the nulls. Only the explanatory comments differ; the logic is
   character-for-character equivalent.
2. *Handler prelude* (Finding #6). `applyApiHeaders(res); if (!methodGuard(req, res)) return; if (!originGuard(req, res)) return;`

**Best Practices Review.** The load-bearing constraint is `viz/README.md`
§Architecture's one-way tier rule. The shared reader needs `node:fs/promises`,
`node:path`, `fsSafe`, and `tasknote-parse`, so it is Node-only tier. Three
homes were considered:

- *Into `fsSafe.ts`* — rejected. `fsSafe` is domain-free ("path-safe fs
  helpers", imports nothing local); pulling in `parseTasknote` and the `Tasknote`
  type would give it tasknote-domain knowledge and make it a non-leaf.
- *Into `archiveCache.ts`, imported by `devApi`* — rejected. This is exactly the
  `archiveCache` ↔ `devApi` edge [[FE-088.2]] refused to create, and the active
  list is not archive-cache business.
- *New leaf module `viz/src/tasknoteRead.ts`* — chosen. Both callers import
  downward from a leaf that imports only other leaves. This is precisely the
  shape [[FE-088.2]] itself used for the containment primitives: *"`fsSafe.ts` is
  the existing home for tolerant fs primitives — the containment helpers belong
  there, not duplicated into two call sites."* A new leaf answers its objection
  rather than overriding it.

For `guarded()`, the value is enforcement, not line count: nesting the handler
body inside the wrapper makes it structurally impossible for a future handler to
ship without headers + method guard + origin guard. A `prelude(req, res): boolean`
helper would save the same lines while still being forgettable.

**Implementation Notes:**

**Pattern survey.** The extraction follows the shape [[FE-088.2]] used for the
containment primitives themselves: a leaf module both call sites import
downward, rather than one caller importing the other. `viz/src/tasknoteRead.ts`
imports only `node:fs/promises`, `node:path`, `fsSafe`, and `tasknote-parse` —
all leaves or shared-pure — so `viz/README.md`'s one-way tier rule holds and no
`archiveCache` ↔ `devApi` edge exists. `guarded()` follows the combinator shape
already in the file (`methodGuard` returning a continue/stop boolean), raised one
level so the handler body is nested inside the guard rather than sequenced after
it.

**The fix.**

- `viz/src/tasknoteRead.ts` (new, 54 L) — `readTasknoteDir(realBase, dir)`: the
  single `safeReaddir` → keep `.md` → `realpathWithin` → `readFile` →
  `parseTasknote` → drop-on-failure loop. The two silent-drop rationales and the
  root-anchored-containment rationale are consolidated into its header from the
  two call sites, including the [[CORE-222]] symlinked-root case and the note
  that callers keep the `realRoot === null` early return (TypeScript cannot
  narrow a captured `string | null` inside the `files.map` closure — [[FE-088.2]]'s
  reason for that shape, preserved).
- `viz/src/archiveCache.ts` (+4/−29) — `readArchive`'s per-area body collapses to
  one `readTasknoteDir` call. Drops the now-unused `readFile`, `parseTasknote`,
  and `realpathWithin` imports; the root-anchoring comment stays because it
  explains why *this* caller passes the root rather than `archiveDir`.
- `viz/src/devApi.ts` (+35/−59) — `guarded()` added; all six handlers route
  through it and shed the three-line prelude. `createActiveHandler`'s 23-line
  loop collapses to one `readTasknoteDir` call, dropping the `join`,
  `parseTasknote`, `safeReaddir`, and `Tasknote` imports.
- `viz/README.md` (+4/−3) — the new Node-only module added to the layout sketch,
  to the tier table's role summary, and to the `src/ui/` no-Node-import rule's
  module list (an `src/ui/` file importing `tasknoteRead` must be caught by that
  eslint rule like every other Node-tier module).

**`guarded()` typing.** The wrapper is uniformly `async`, which widens
`createProjectsHandler` and `createEventsHandler` from `Handler` to
`AsyncHandler`. Two alternatives were weighed and rejected: an overload pair
(`Handler → Handler`, `AsyncHandler → AsyncHandler`) preserves the narrower types
but lies at runtime on the guard-rejection path, where the "async" branch returns
`undefined` rather than a promise; and a `prelude(req, res): boolean` helper saves
the same lines while remaining just as forgettable as the three lines it replaces,
which forfeits the only reason to do Finding #6 at all. The widening is safe
because an async body runs synchronously up to its first suspension and neither
sync handler contains an `await` — so `createEventsHandler` still registers its
SSE client and writes its preamble before returning, and the existing synchronous
assertions in `devApi.test.ts` pass untouched. Connect ignores middleware return
values, and `createPlanHandler` had already proven the async shape works there.

**Minimal refactor gate.** Nothing beyond the two named findings was
restructured. **Deferred:** `projectFromQuery(req, projects)` + the
`if ('error' in project) { endPlain(res, 400, project.error); return; }` block is
duplicated across the four project-scoped handlers — a third, distinct
duplication the PLAN line does not name. A `guardedProject()` variant composing
over `guarded()` would fold it, but it is not required by Acceptance and folding
it would widen a Low-priority cleanup into a handler-signature change. Logged,
not done — the same call [[FE-088.2]] made about this task.

**Accepted residual, unchanged.** [[FE-088.2]]'s realpath → readFile TOCTOU
window survives verbatim; moving the two syscalls into one helper neither widens
nor closes it.
