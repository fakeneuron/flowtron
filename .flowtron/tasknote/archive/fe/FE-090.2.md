**Implementation Notes:**

**Dep bumps** (`viz/package.json` + lockfile): `eslint` 9.39.4 → 10.9.0, `@eslint/js` 9.39.4 → 10.0.1, `typescript-eslint` 8.59.4 → 8.67.0, `jsdom` 26.1.0 → 30.0.1, `chokidar` 3.6.0 → 5.0.0. ESLint 10 needed **zero** config changes — `eslint.config.js` was already flat-config, and both `typescript-eslint` and `eslint-plugin-react-hooks@7.1.1` already peer `^10.0.0`. jsdom 30 needed no test changes.

**chokidar 5 migration.** `watchSets()` now returns literal paths — `[planPath, tasknoteDir]` per project on hot, `[archiveDir]` on archive — instead of assembling globs. The retired reach is re-expressed in three places:
- `WATCH_HOT_OPTIONS`: `depth: 1` → **`depth: 0`** (immediate children of `tasknoteDir`, matching the old one-level glob, and stops the hot watcher descending into `archive/` beneath it). `usePolling: true` kept per [[CORE-222]].
- `archiveWatchOptions(roots)`: `depth: 2` → **`depth: 1`** (reaches `<area>/<file>.md`). `usePolling: false` kept per [[CORE-431.2]].
- `ignoreNonMarkdown` / `ignoreOutsideArchiveArea(roots)` predicates. Both deliberately pass directories and stats-less pre-checks — chokidar applies `ignored` to *traversal* as well as events, so pruning a directory would stop the watcher ever reaching the files inside it.

Depths were derived empirically against chokidar 5 in a scratch probe, not assumed: chokidar 3 measured `depth` from the glob base, so the old `1` / `2` were not portable.

`ignoreOutsideArchiveArea` exists because `depth: 1` alone is **looser** than the retired glob — it would also admit a stray `.md` sitting directly in an archive root, silently undoing [[FE-076]]'s narrowing to the exact shape `readArchive` reads. The predicate requires `dirname(dirname(path))` to equal a watched root.

`createOnWatchEvent` gained one guard: `if (!filepath.endsWith('.md')) return;`. chokidar reports `addDir` / `unlinkDir`, which the old globs never matched, and `ignored` cannot suppress directory *events* without also pruning traversal — so the file-only reach is restored at the handler instead. Verified live (Testing Notes case 4).

**Node floor.** `viz/package.json` `engines.node` `">=20"` → `"^22.22.2 || ^24.15.0 || >=26.0.0"`, `.github/workflows/ci.yml` `node-version: 20` → `24`, `docs/CONVENTIONS.md` "on Node 20" → "on Node 24".

⚠️ **Deviation from the approved option text.** The gate answer described `engines.node: ">=22.22.2"`; I mirrored jsdom 30's own range instead. `">=22.22.2"` would have *falsely* claimed Node 24.0–24.14 works — jsdom 30 requires `^24.15.0` on the 24 line — so a developer there would hit a confusing runtime failure with no engines warning. The approved intent (raise the floor for jsdom 30; CI on 24) is unchanged; only the precision differs.
