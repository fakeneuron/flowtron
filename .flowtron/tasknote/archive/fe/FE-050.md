# FE-050 | originguard-referer-port

[← PLAN.md](../PLAN.md) · 🟢 In progress

## 🎯 Goal

Make the originGuard referer fallback check port-strict (using `URL.origin` + `ALLOWED_ORIGINS`) to match the exact-origin semantics of the primary `Origin` header check.

## ⚡ Notes

**Relevance:** Proceed — single-file behavior fix, clear diff, no design tradeoffs.

**Drift check:** `originGuard.ts:32` still reads `new URL(referer).hostname` checked against `ALLOWED_HOSTNAMES` — confirmed asymmetry. The PLAN.md description is accurate.

**Archive skim:** FE-049 covers a test deflake in App.test.tsx, no overlap with originGuard logic.

**Pattern survey:** `ALLOWED_ORIGINS` is already the canonical allowlist used by the primary Origin check. The fix makes the referer path uniform with that check. `ALLOWED_HOSTNAMES` exists solely for the referer path; removing it is the correct cleanup.

**Implementation:** Changed `new URL(referer).hostname` → `new URL(referer).origin`; switched the check from `ALLOWED_HOSTNAMES` (hostname-only set) to `ALLOWED_ORIGINS` (full origin set); removed `ALLOWED_HOSTNAMES` export. Added two new tests: one covering a valid same-origin referer (`http://localhost:5120/path`) that must pass, and one covering a same-hostname/wrong-port referer (`http://localhost:3000/path`) that must now be blocked.

**Docs touched:** no change

## ✅ Recap

Replaced hostname-only referer check with full-origin check (`URL.origin` vs `ALLOWED_ORIGINS`), removing the now-unnecessary `ALLOWED_HOSTNAMES` set. A referer like `http://localhost:3000/path` is now correctly blocked, symmetric with how `Origin: http://localhost:3000` is already blocked. Added two tests that cover the previously untested allowed-referer and wrong-port-referer cases.
