### Palette × density × visibility interaction analysis (code-level)

- **Palette × density:** palette tokens are color-only (`bg-*`, `text-*`, `border-*`, `ring-*`); density tokens are spacing/typography (`px-*`, `py-*`, `gap-*`). Orthogonal at the className level — no shared utility prefix, no token combination that produces conflicting output. Each palette × each density mode = independent application of two disjoint Tailwind utility sets.
- **Palette × visibility:** visibility prefs toggle which UI surfaces render (row chips on/off, detail sections on/off, starter sections on/off). All surfaces consume palette tokens via `usePalette()`; hiding a surface doesn't strand palette state. Each palette × each visibility config = renders the same chosen surfaces in the chosen palette.
