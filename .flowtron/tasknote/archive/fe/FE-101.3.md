# FE-101.3 | targeted-sse-refetch

[← PLAN.md](../PLAN.md) · 🟢 In progress · 🔗 [[FE-EPIC-101]] · [[FE-101.2]]

## 🎯 Goal

Carry a scope on the SSE `change` wire so an attributed event refetches only the endpoints its watched path can have invalidated, instead of all four.

## ✅ Acceptance

- [x] The SSE `change` payload carries a scope: `{"project":"<name>","scopes":["plan"|"active"|"archive", …]}`. The codec (type, encoder, decoder) lives in `viz/src/sseChange.ts` — the shared Node-free tier both the plugin and the browser import (`viz/README.md` §"Dependency direction").
- [x] `projectForPath` (`watchSet.ts`) returns the scope alongside the project: `planPath` → `plan`, `dirname === tasknoteDir` → `active`, `startsWith(archiveDir)` → `archive`.
- [x] `createChangeBroadcaster` accumulates a scope **set** per project across the debounce window and flushes one payload per project carrying that set. An unattributed event in the window still collapses the whole flush to a single `{}` (CORE-431.3 fail-open).
- [x] The `plan` scope refetches **both** `/api/plan` and `/api/plan-archive`. PLAN-ARCHIVE.md is deliberately unwatched, and rotation always edits PLAN.md in the same motion, so `planPath` is the only signal rotated history moved ([[FE-094]]).
- [x] An attributed `change` refetches only its scopes' endpoints. Fail-open is preserved for every other path: `{}` / absent `scopes` / an unrecognized scope value / reconnect-after-drop / the `LIVE_RECOVERY_MS` degraded poll / the manual keyboard reload all still refetch all four.
- [x] The [[FE-072]] monotonic load guard becomes **per-scope**, so a later narrow load cannot discard an in-flight broader one's other slices (and vice versa). `activeProjectRef` cross-project guard unchanged.
- [x] `tasknotesById` is derived from separate active/archived slices, so an `active`-only refetch still drops a deleted tasknote instead of leaving a stale entry — and archived-only entries survive it.
- [x] New tests cover: scoped codec round-trip + unknown-scope fail-open; `projectForPath` scope per path kind; broadcaster per-project scope coalescing; and, in `useProjectData`, that an `archive`-scoped event fetches exactly `/api/archive`, a `plan`-scoped event fetches exactly the two plan endpoints, and an unattributed event fetches all four.
- [x] Endpoint-fetch reduction measured on flowtron's own board (bytes per typical tasknote edit, before vs. after) and recorded in Testing Notes.
- [x] `npm --prefix viz test`, `npm --prefix viz run typecheck`, and `npm --prefix viz run lint` all clean.

**Discovery Notes:**

**The seam.** `projectForPath` (`watchSet.ts:43-53`) already distinguishes the three path kinds — it tests `filepath === p.planPath`, then `dirname(filepath) === p.tasknoteDir`, then `filepath.startsWith(p.archiveDir)` — and then throws that knowledge away by returning only the project. The whole server side of this task is *stop discarding it* and thread it through `schedule` → `flush` → the payload.

**Path → scope → endpoint map.**

| Watched path | Scope | Endpoints refetched |
|---|---|---|
| `<root>/.flowtron/PLAN.md` | `plan` | `/api/plan` **+** `/api/plan-archive` ([[FE-094]]) |
| `<root>/.flowtron/tasknote/*.md` | `active` | `/api/active` |
| `<root>/.flowtron/tasknote/archive/<area>/*.md` | `archive` | `/api/archive` |
| *(unmatched / unattributed)* | — | all four (fail open) |

Ordering is safe: `archiveDir` is `tasknoteDir/archive`, so an archive file's `dirname` is `…/archive/<area>` and never equals `tasknoteDir`. The existing precedence already relies on this.

**Why the client state has to split.** Today `load()` rebuilds one merged map from a complete pair of responses:

```ts
const merged = new Map(archived.map((t) => [t.id, t]));
for (const t of active) merged.set(t.id, t);
setTasknotesById(merged);
```

Deletion is handled implicitly — a tasknote that vanished from `/api/active` is simply absent from the rebuild. Under an `active`-only refetch there is no `archived` half to rebuild from, and a `setTasknotesById(prev => …)` merge would leave the deleted note stranded in `prev` forever. Holding `activeById` and `archivedById` as separate state and deriving the merge in a `useMemo` keeps per-slice deletion exact and preserves the original precedence (active wins on an id present in both).

**Why one `loadSeq` stops working.** [[FE-072]]'s guard is `loadSeqRef.current !== seq`, and it is correct today only because *every load is a full load* — discarding a superseded response loses nothing, since the winner carries the same four slices. With partial loads: an `active` change at t=0 stamps seq 1; an `archive` change at t=10 ms stamps seq 2; if the active response lands last it is discarded and the active slice is silently lost until the next event. Per-scope counters (`{ plan, active, archive }`, each stamped and checked independently) restore the invariant — a response is discarded only when *its own slice* has been superseded.

**A second, smaller ordering hazard.** `setLoading(false)` currently runs in `finally` for every load. Once a scoped refresh can outrun an in-flight initial load, it would clear the skeleton before the first full load commits — an empty-board flash. Gating that write on `showSkeleton` confines it to the loads that actually raised the skeleton.

**Fail-open inventory** (what must still refetch all four, per [[CORE-431.3]] / [[FE-064]] / [[FE-088.3]] and the operator's answer above): initial mount · project switch · unattributed `{}` · a payload with absent, empty, or unrecognized `scopes` · reconnect after a drop · the `LIVE_RECOVERY_MS` poll · the `App.tsx` keyboard reload.

**Expected saving.** The common case by far is editing one active tasknote, which today costs `plan + plan-archive + active + archive` ≈ 1.83 MB and after this costs `active` ≈ 2.7 KB. A PLAN.md edit drops from ≈ 1.83 MB to ≈ 60 KB. Only a genuine archive write still pays the 1.77 MB — which is the shape the parent epic asked for: cost bounded by *what changed*, not by archive size.

**Final Summary:**

The viz board now refetches only what actually changed. An SSE `change` event carries the *kind* of watched path that fired — `plan` / `active` / `archive` — and the client fetches just that scope's endpoints instead of all four. **Editing a tasknote drops from 1,866,363 B to 4,821 B (−99.74%)**; a PLAN.md edit drops to 87,654 B (−95.3%). That first case is the one that fires on every checkbox tick during a `/ft-task` run, so it is the one that mattered.

**Changed files** — eight, +617/−137. Four source: `viz/src/sseChange.ts` (scope vocabulary; `projectFromChangeData` → a single-parse `parseChangeData` returning `{ project, scopes }`), `viz/src/watchSet.ts` (`projectForPath` returns the path kind it already computed instead of discarding it), `viz/src/flowtronWatch.ts` (broadcaster accumulates a `Set<ChangeScope>` per project across the debounce window; `schedule` takes one `ChangeHit` so a project-without-scope is unrepresentable), `viz/src/ui/useProjectData.ts` (per-scope load sequencing, conditional fetch, per-slice commit, active/archived state split). Four matching test files: 23 new cases, 481 → 504.

**Verification** — `npm --prefix viz test` 25 files / 504 tests passing; `run typecheck` and `run lint` clean. Lint is load-bearing: the `src/ui/**` `no-restricted-imports` rule ([[FE-97]]) is what proves the scope vocabulary landed in the shared Node-free tier rather than being smuggled in from `watchSet`. Measured end-to-end against a live dev server on flowtron's own tree, reading `/api/events` with `curl -N` while touching each path kind — all three scopes attribute correctly, and an archive-move burst (tasknote + archive touched inside one 200 ms window) coalesces to a single `{"scopes":["archive","active"]}` flush. Operator visually confirmed the board, including that a completed task's detail panel survives an `active`-scoped update.

**Refactors** — one made, and it was mandatory rather than opportunistic: `tasknotesById` split into `activeById` / `archivedById` with a `useMemo` merge. A single merged map updated in place cannot express deletion, so an `active`-only refetch would strand a just-archived tasknote in the map forever. One extra correctness fix not implied by the PLAN line: `setLoading(false)` moved behind the `showSkeleton` guard, because a scoped refresh can now outrun an in-flight initial load and would otherwise flash an empty board. Deferred deliberately: `planArchivePath` was **not** added to the watch set — pairing both plan endpoints under one scope reproduces today's behaviour exactly, and watching it would be a real behaviour change dressed as a refactor.

**Documentation** — no drift across all 18 AI-referenced docs, verified by grep rather than by category; `SECURITY.md` and `SPEC.md` checked individually.

**Maintainability** — the change is a widening, not a new mechanism: the same four-station pipeline [[CORE-431.3]] built now carries a project *and* a kind, and the two alternatives that note rejected (a client→server channel, a narrowed watch set) stay rejected. Public surface grows by four exports, each with a real caller. Two subtleties are now pinned by tests that fail against the old design rather than merely describing the new one — the per-scope sequencing ([[FE-072]]'s single counter was safe only while every load was complete) and the slice split. The remaining cost is the 1.77 MB archive payload on a genuine archive write, which is [[FE-101.5]]'s ground, not this task's.
