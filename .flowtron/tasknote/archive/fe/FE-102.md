**Discovery Notes:**

**The vector, precisely.** `default-src 'none'` restricts what a document may *load*; it says nothing about who may *embed* it — `frame-ancestors` is a separate directive with no fallback. So today nothing stops a page at `https://evil.example` from embedding `http://localhost:5120/api/events` in a `referrerpolicy="no-referrer"` iframe. Cross-origin iframe navigation sends no `Origin` (it's a GET navigation, not a CORS request) and, with that referrer policy, no `Referer` — so `originGuard` sees a bare request and returns `true` by design. `methodGuard` passes it too (GET). The frame then holds an SSE slot. Ten of them exhaust `MAX_SSE_CLIENTS`, and the operator's real board starts taking the 503 from FE-062.

**Two independent fixes, deliberately both.** `frame-ancestors 'none'` stops the browser rendering the response in a frame at all; the `Sec-Fetch-Site` check stops the request server-side regardless of framing (it also covers a plain cross-site link or `window.open`). Either alone would blunt the iframe case; together they cover the vector at both ends, and the server-side one is the load-bearing half because it doesn't depend on the client honoring CSP.

**Why this isn't exfiltration.** Same-origin policy already prevents the embedding page from reading the framed response body. The loss is availability of the operator's own live-update stream — matching the audit's Medium.

**Finding #2 (Low).** Independent of the above: `projectFromQuery` interpolates the raw `?project=` value into a `console.error` template. The value never reaches the wire (FE-047 saw to that), but a name containing `
` can inject a forged line into operator stderr. `JSON.stringify` quotes and escapes it in one call, which is the minimal fix and keeps the name readable in the log.

**Implementation Notes:**

Three edits, each a single expression, no new module or export.

1. **`originGuard.ts`** — a `req.headers['sec-fetch-site'] === 'cross-site'` early return with a 403 `Forbidden: cross-site request`, placed ahead of the `Origin` / `Referer` logic. A strict equality check is deliberate: Node collapses duplicate header instances into a comma-joined string, so a forged `Sec-Fetch-Site: cross-site, same-origin` fails the equality and falls through to the existing exact-origin checks rather than being smuggled past them. The comment records the vector, the ordering reason, and why an absent header must still pass.
2. **`devApi.ts`** — `API_SECURITY_HEADERS`' CSP becomes `default-src 'none'; frame-ancestors 'none'`. `applyApiHeaders` is unchanged, so the new directive inherits the existing "applied ahead of every guard clause" property and reaches 400/403/405/500/503 bodies for free.
3. **`devApi.ts`** — `projectFromQuery`'s stderr line wraps the caller-supplied name in `JSON.stringify`, which quotes and escapes control characters in one call. This is the stderr half of the FE-047 log-detail/return-generic split; the wire-side response is untouched and still returns the fixed `unknown project`.

**Pattern survey:** no new shape. Every existing guard in this pair (`methodGuard`, the two `originGuard` branches) is early-return + `endPlain(res, <code>, <fixed string>)` + `return false`; the new check is that shape verbatim. `frame-ancestors` was added to the API CSP only — `vite.config.ts`'s `DEV_CSP` already carries it, and the comment at `devApi.ts:15-19` records the standing decision to keep the page CSP and the API CSP separate rather than share a constant. **Minimal refactor gate:** no refactor.
