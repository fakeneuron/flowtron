# FE-115 | watcher-error-listener

[← PLAN.md](../PLAN.md) · 🟢 In progress · 🔗 [[FE-090.2]] [[FE-091]] [[CORE-431.2]]

## 🎯 Goal

Attach `'error'` listeners to both chokidar watchers (hot + archive) in `viz/vite.config.ts` through a tested `createOnWatchError` factory in `viz/src/flowtronWatch.ts`, so an EMFILE/EPERM/EBUSY watcher fault logs to stderr and the dev server keeps serving instead of crashing on an unhandled `'error'` emit.

**Implementation Notes:**

- `viz/src/flowtronWatch.ts` (+17): `createOnWatchError(label: string): (error: unknown) => void`. Takes `unknown` because that is how chokidar types the `'error'` payload; reads `code` structurally (Node errno errors are plain `Error`s with an ad-hoc `code`), uses `message` for `Error`s and `String()` otherwise. One `console.error` line: `[flowtronWatch] <label> watcher error (<code>): <message> — watching degraded until the dev server restarts`. The trailing clause is the degrade contract stated to the operator — nothing retries or re-watches.
- `viz/vite.config.ts` (+3): imports the factory; `hotWatcher.on('error', createOnWatchError('hot'))` and `archiveWatcher.on('error', createOnWatchError('archive'))` directly after each `'all'` attach.
- `viz/src/flowtronWatch.test.ts` (+42): three cases — errno-coded `Error` (EMFILE), plain `Error` (no code segment), non-Error payloads (`'EBUSY'`, `null`) — each asserting the exact stderr line and `not.toThrow()`. `vi.spyOn(console, 'error').mockImplementation(() => {})` keeps the suite quiet, as `devApi.test.ts` does.
