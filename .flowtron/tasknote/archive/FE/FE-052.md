# FE-052 | restore-viz-test-gate

[← PLAN.md](../PLAN.md) · 🟢 In progress

## 🎯 Goal

Bump viz `jsdom` from ^25 to ^26 and restore the full test suite to green under Node 26.

## ⚡ Notes

**Relevance:** Proceed — root cause confirmed, straightforward fix.

**Drift check:** `viz/package.json` jsdom version and `viz/src/test/setup.ts` polyfills — both paths stable, no drift from audit findings.

**Archive skim:** FE-049 (deflake-wikilink-nav-test) referenced jsdom but was a timeout issue, unrelated. No prior tasknotes touch the jsdom version or localStorage polyfilling.

**Pattern survey:** `setup.ts` already polyfills `scrollTo`, `matchMedia`, `EventSource`, `HTMLDialogElement` — same conditional-define pattern extended for `localStorage`/`sessionStorage`.

**Implementation:** Two changes made:
1. `viz/package.json`: bumped `jsdom` from `^25.0.1` to `^26.0.0` (installed 26.1.0).
2. `viz/src/test/setup.ts`: added `localStorage`/`sessionStorage` polyfill.

Root cause: Node 26 defines `globalThis.localStorage` as an experimental property (returns `undefined` without `--localstorage-file`). Vitest's `getWindowKeys` filter skips copying jsdom's Storage implementation to the test global whenever the key already exists in Node's global — and `localStorage` is not in vitest's `KEYS` allowlist, so it stayed as Node's undefined. The jsdom bump alone was insufficient; the polyfill is the actual fix. The audit's diagnosis of the symptom was correct (44 failing tests, localStorage undefined), but the prescribed remedy (version bump alone) was incomplete.

**Docs touched:** `viz/src/test/setup.ts` comment updated inline (explains Node 26 root cause). No AI-referenced doc changes.

## ✅ Recap

Bumped jsdom ^25→^26 and added a localStorage/sessionStorage polyfill in `setup.ts` to work around Node 26's experimental Storage globals shadowing vitest's jsdom population. Suite went from 44 failing to 172/172 green. CORE-280 (add test gate to `/ft-release`) is now unblocked.
